## 一、用户想要的是什么

想让学长"按我的习惯来"（注释密度、测试命令别加 `-n auto`、回复里不要 emoji、
改完必须跑快车道），今天只有两条路，都不对：
1. 改仓库里那份 `system_prompt.md` —— 它是**打包内置的只读资源**
   （`paths.py:91` `SYSTEM_PROMPT_PATH = RESOURCE_DIR / "system_prompt.md"`），
   改了影响所有拿到这个包的人，而且换机器就没了；
2. 记进长期记忆（`/remember` 或顶栏「🧠 记忆」记一条）—— 但记忆存的是**事实与偏好**，
   每轮作为上下文喂给模型，不承担"规矩"的角色，也不保证被遵守。

Codex 那一层是分层指令文件（全局 → 项目，`AGENTS.md`），ZCode 用静态指令文件
（`AGENTS.md`）锁工程标准。缺的就是这一层。

## 三、真正的缺口（三件，按风险排）

### L1 · 用户级一份指令文件（低风险，先做）
- `<APP_DIR>/INSTRUCTIONS.md`（名字待定，见 §七.1）：存在就**追加**在内置提示词之后、
  各段 prompt section 之前；不存在就什么都不做（**不创建、不提示"你应该写一份"**——
  那是把工程习惯塞给非技术的同学）。
- 有大小盖（例如 ≤8 KB）与"读不到/太大"两种情况的如实回显：截断时必须让模型和界面都知道
  "这份被截了"，不许静默吃掉半句规矩（与 `_truncate`、剪枝那套同一口径）。
- 出口：💾 数据面板那行给出它的路径与"打开它"（复用既有的"开本机文件"真路），
  以及对话里能被问出来（「我的工程规矩是什么」→ 读这两份文件回话）。

### L2 · 工作区级一份（中风险，依赖 L1）
- `<workspace>/AGENTS.md`（或同族名字）：**只在当前工作区生效**，优先级高于用户级。
  这一层的价值在 v0.9.98 的 worktree 之后才真正成立 —— 两个工作副本可以有不同规矩
  （一份在改前端、一份在跑数据迁移），这正是分层要解决的场景。
- 必须处理的三件事：①**它不在工作区内时不算**（`resolve_path`/敏感路径那套围栏同样适用，
  不能因为"这是配置文件"就读 `..` 之外的）；②换工作区后**重新装配**（不能沿用上一份，
  否则 A 项目的规矩管了 B 项目）；③子代理默认**继承用户级、不继承项目级**（派到
  `explore`/`audit` 档的活未必在同一目录），这条要写死并单独有测试。

### L3 · 让"这一轮用了哪几层"可见（低风险但最能救信任）
- 任务面板/`/history` 里列出："内置 + 用户级（N 条）+ 项目级（M 条）"，**只报份数与来源，
  不重复贴内容**。这一条是防止"我明明写了规矩它不听"变成扯皮：至少能确认它有没有读到。
- 不做"命中了哪条所以这么做"的因果归因（那是猜，见 §五.4）。

## 四、必须写死的四条口径

1. **越近的越大，但红线不参与覆盖**：`内置红线段 > 项目级 > 用户级 > 内置一般段` 这种
   "就近优先"只对**风格与流程**有效。沙箱边界、敏感路径硬禁、"没答当没同意"、
   不编数字、通知只记类别不记正文 —— 这一批**写死为不可覆盖**，
   并在装配时把项目/用户文件里试图推翻它们的行**剔出来单独回执**：
   「项目 AGENTS.md 第 3 行要求跳过确认，与红线冲突，我没有采纳」——
   不静默、不照做、也不假装照做。
2. **它不是外部内容，但按半可信处理**：项目文件可能是别人 clone 带来的
   （仓库里放一份 `AGENTS.md` 就等于所有拉到它的人都会被喂话），所以：
   ①不因为它是"配置"就绕开注入防御的读取口径；②首次在当前工作区读到它时，
   用一次 `ask_user`/确认告知"这个项目自带了一份指令，我要按它干活"，
   让用户有点头或拒绝的机会（这条与 `permissions.json` 首次批准同构，那套留痕可直接借形）。
3. **不进迁移包的默认值**：这类文件是否随「我的数据」导出，要按 `mydata.TABLE` 的
   六分类逐条定（它是"设置与偏好"还是"我的内容"？）；网页版访客一律不给（`web_profile` 表态），
   服务器上一个访客的项目文件不能给主人的会话定规矩。
4. **不许写"命中第几条"**：能报"读到了、几行、来自哪份"，不能报"我之所以这样写是因为你
   第 2 条" —— 那是把模型的自述当因果证据，正是这个项目反复清退的装饰。

## 五、刻意不做 / 不要这样做

1. **不做可覆盖红线的机制**（连"管理员模式"都不做）：沙箱那套的定位写得很清楚
   —— "这套边界不是防火墙"，四条已知限界供确认框引用；再加一层"文件可以推翻它"，
   等于把那四条已知限界变成唯一一条真限界（谁都能写文件）。
2. **不做规则引擎/条件生效**（"若匹配 *.py 则…"）：先要真实需求，现在一份纯文本足矣；
   做成条件系统要回答求值顺序、冲突消解，代价是数量级的。
3. **不做团队同步/云配置**：本地优先边界（`project-local-first-scope`）。
4. **不把《使用说明》的写法搬进模型**：那一份是给人的，这一份是给模型的，两份内容重叠
   就要有第二处真相 —— 明确不互抄，宁可各写各的短句。
5. **不新增落盘"指令命中账"**：L3 只现算。真要做统计就得交四处登记税
   （`.gitignore` + `state_files.SHIP_NEVER` + `mydata.TABLE` + 打包清理），
   目前没有非做不可的理由。
6. **不静默创建模板文件**（不主动往 `APP_DIR` 写一份"示例指令"）：
   装好的包里凭空多一个用户没要的文件，是最容易被当成"学长自己乱写东西"的那类事。

## 六、代价与验证口径

- 后端：`app_setup.py` 加 `_read_instructions(workspace)`（两级 + 盖 + 剔除红线冲突行）
  （约 70 行）；`paths.py` 加两个常量；装配顺序单测。
- 测试（这一件的价值几乎全在针上）：
  ①两级都存在时，拼接顺序确定（把三份内容喂不同 marker，断言 marker 顺序）；
  ②用户级存在、项目级缺失 → 输出里没有项目段那句话（不写"本项目未提供"这种装饰）；
  ③项目文件试图推翻红线 → **被剔出的那行在回执里出现，且最终提示词里不出现**（两头都断言）；
  ④工作区切换后项目级跟着换（拿两个 tmp 工作区各放一份，断言 A 的 marker 不出现在 B 的装配里）；
  ⑤子代理只继承用户级（派一发 `explore`，扫它拿到的 prompt）；
  ⑥超大文件被截时那句话说得出"截了多少"；
  ⑦`resolve_path` 围栏对项目文件同样生效（放一份在 `..` 外的路径，断言不读）；
  ⑧首次读到项目级会有一次告知/点头（复用 ask_user 的话术与 `abandon_pending` 语义：
  **没答不算同意**，不算同意就不采纳）；
  ⑨扫输出不含绝对路径泄漏（网页版与导出面各一例）。
- 登记税：`state_files` / `.gitignore` / `mydata.TABLE` 按 §四.3 的定论交税；
  `packaging/*.spec` 若要把内置模板继续收包则核一遍；冻结针加 `build_system_prompt`
  与读取函数；README 配置/文件表 + 包内《使用说明》要不要各写一句（编号那笔债还压着，
  见 §6 #35 与本方案第七节）。
- 彩排照例：全量不带 `PYTHONIOENCODING`、`check_docs.py --collect`（**数从干净树当场量**）、
  前端 JS 闸带该 env。

## 七、要用户拍的板（四件事）

1. **名字与层级**：`AGENTS.md`（跟三家一致、clone 来的仓库自带也能直接被喂）
   还是 `INSTRUCTIONS.md`（不装成行业标准）？两级同名 vs 用户级另起一名，我推荐
   项目级 `AGENTS.md`、用户级 `~/<数据目录>/AGENTS.md`，一个词两个位置，好解释。
2. **首次采纳要不要点头**（§四.2）：我推荐要（这是"别人写的文件给我定规矩"），
   代价是每换一个含 `AGENTS.md` 的目录多一次打扰 —— 可以用"同一份内容指纹只问一次"
   来收（与 `permissions.json` 的内容指纹批准同构，那套已经落地过）。
3. **子代理安不安全继承项目级**：默认不继承（我推荐，理由是派出去的档未必在同一目录），
   还是同工作区就继承？
4. **排不排在前面三件之前**：这一件不像 ①（改动审查）和 ②（验收）那样直接改变
   "它说的话有没有凭据"，它改的是"你能不能把自己的习惯交给它"。
   真实价值取决于你到底会不会去写那份文件 —— 这个只有你知道。

## 八、落地时补的账(v0.9.101,做了 L1/L3;L2 已由 v0.9.100 F1 落地)

- **名字按 §七.1 的推荐定了**:项目级 `AGENTS.md`(F1 原样),用户级**同名不同位** ——
  `<数据目录>/AGENTS.md`,一个词两个位置,少一个要解释的名字。
- **子代理继承项目级沿用 F1 的口径**(稿 §三.2③ 原本写"默认不继承"):这个 app 里子代理
  就在同一个 `ctx.workspace` 干活,不是"派到别的目录",所以继承是对的。这条以实测情况为准。
- **§四.2「首次采纳点头」没做**:它要一份"已告知指纹"落盘(第四本账 + 四处登记税),
  而项目级从 v0.9.100 起就在注入 —— 现在补点头等于给已经在用的东西追认。真要做,
  先答"这份文件是不是别人 clone 带来的"这个场景有没有真实出现。
  - **v0.9.127 补做了(用户点名)**,上面那三条顾虑各有一个答案记在这儿:
    ①**没开第四本账** —— 采纳记录并进 `perms-trust.json` 里这个工作区**同一行**
    (`agents_sha256`),因为这两件本来就是同一件事:"别人写进这个目录的文件,你核对过
    才让它对你说话"。代价是 `trust()` 从整行盖掉改成合并、`revoke()` 只撤白名单那半截
    (两次独立的点头不许互相抹掉,各有针)。②**追认是刻意的**:改成"没采纳就不注入"
    之后,老用户那份一直在起作用的 `AGENTS.md` 会在下一次开会话时被问一句 ——
    这正是"这句点头到底要不要"的现场回答机会,而不是悄悄改口径。③**"场景有没有真实
    出现"不该由我替你判断**:clone 来的仓库带一份给 agent 定规矩的文件,在差距矩阵里
    是八家都认的攻击面,而本项目其它处的立场一直是"文件不能自证清白"(hooks 只从安装
    目录读、`permissions.json` 要另点一次头)。
    口径细节:**只认明确点到「采纳」**;「按推荐」不算(那张卡的推荐位是程序排的);
    没提问通道的形态(无头、网页版)一律按没采纳,并说一次「没采纳」而不是刷屏。
    **还没做**:界面上「采纳 / 撤销采纳」那颗按钮(桥层不加没人调用的方法)、
    以及给无头模式一条显式批准的口子 —— 两条都记在 `HANDOFF.md` §6 51(g)。
- **§四.1「把试图推翻红线的行剔出来并回执」没做**:中文文本上的启发式匹配做不准就会写成
  一道假防线。红线本来就由代码把守(权限门/沙箱/确认门都不读这两份文件),所以这里选了
  一句**说得出口的事实**:`INSTRUCTION_GUARD` 两段各带一次「这些改不动它们」,
  并有针数它的出现次数 —— 报"读到了几行"可以,报"命中了第几条"不行(§四.4 原样保留)。
- **L3 落在侧栏「📐 指令:内置 + 用户级(N 行) + 项目级(M 行)」**,`get_info()` 带出,
  网页版按 §四.3 明确抹空(那一行报的是主人本机写了几行规矩)。
- **L3 在 v0.9.103 也搬进了终端**(`/instructions`):同一份 `instruction_layers()`,报哪几层真读到、各几行、有没有被截(`AGENTS_CHAR_LIMIT` 那一截要说得出口),末尾跟着 `INSTRUCTION_GUARD` 那句「这些改不动红线」。§四.4 那条禁令原样守着 —— 只报读到几行,不报「我这么做是因为你第 N 条」。一份都没有时说的是实话(「用户级、项目级都没读到」+ 去哪儿写一份),不写「本项目未提供」那种装饰。

## 九、第三级(子目录就近)落地记录 · v0.9.149

L1/L2/L3 是"**哪几个位置**放规矩",第三级是"**哪个目录**的规矩管哪个文件"。它登记了 7 次以上、跨度最长,而**卡住的不是实现,是一个机制选择**(预载全部层 vs 触达时注入)。最后按**触达时注入**做,理由与取舍记在 `HANDOFF.md` §6 第 59 条与 §2 的 v0.9.149 那一行;这里只记本文那几条口径**最终落在哪儿**:

- **取层锚点是文件,不是 cwd**(§三那两条路的取舍):`read_file`/`write_file`/`edit_file` 取参数里的 `path`,`apply_patch` 走 `patch.patch_paths` 把补丁里每一份都取出来。**为什么不按 cwd**:学长从不 chdir,cwd 永远只是工作区根 —— 拿它当锚点等于这一层永远只有一份,与两级没有区别。
- **顺序 = 根 → 最近**,这个顺序本身就是 §四.1 那条"越近的越大"的实现(越近的排在越后面,模型读到的后一段更具体)。
- **§四.1 那条红线不参与覆盖**照旧由 `INSTRUCTION_GUARD` 把守,而且**每一层的注入块里都带那句话** —— 只在根那份里说一次的话,子目录那一层看起来就像"更近所以能推翻红线"。
- **§四.2 那条"按半可信处理"在这里更硬了一层**:根那一层今天一次点头就够,而子目录**每层各点一次**。理由就是 §四.2 自己写的那个场景 —— "仓库里放一份 `AGENTS.md` 就等于所有拉到它的人都会被喂话";能放一份就能放十份,一次点头全收了等于把这条防线拆掉。
- **§四.3 不进迁移包**:`agents_layers` 住在 `perms-trust.json`(本机信任账),与 `agents_sha256` 同一个家,不随「我的数据」走 —— 它是"这台机器点过没点头",不是"我的内容"。网页版访客照旧不给(它连提问通道都没有,`_agents_refused` 那条路会说一句"这个界面点不了头")。
- **§四.4 不许写"命中第几条"**:侧栏那一行报的是"目录级 `sub/`(3 行)"这种**份数与来源**,一个字都不提因果。
- **§五 那两条"刻意不做"照旧不做**:仍然没有可覆盖红线的机制,也仍然没有规则引擎/条件生效 —— 第三级只是"多几个位置 + 按目录就近",不是"文件能编程"。
