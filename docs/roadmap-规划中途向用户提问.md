## 一、截图里那张卡是什么(把它拆成可实现的部件)

一块浮在聊天区上的面板,六个部件:

1. 抬头「需要输入」+ 一句规矩:「请回答必填问题;如不再继续规划,请停止当前轮次。」
   —— 注意它给了一条**退出路**,不是把对话锁死。
2. 问题标题(「制作模式」)+ 一段**带理由的推荐**(「我的推荐是「Ink Press 模板模式」:……约 36s / 10 镜头」)。
   —— 推荐不是选项之一就算了,它写清了**为什么**和**代价**。
3. 2-4 个单选项,每项是「标题 + 一行说明」(「Ink Press 模板(推荐)」/「自主自由创作」/「共同创作」)。
   —— 说明那行才是用户能选的依据,只有标题的选项等于没问。
4. 分页「1 / 1」+「上一个」—— 一次一题,可以多题。
5. 「发送回复」按钮。
6. 底下输入框占位变成「请先回答上方的规划问题」—— 界面在提醒"现在轮到你了",
   但**没有禁止**用户改走输入框说话。

同类产品的形状(可作参数契约参照,不抄实现):Qoder 的 AskUserQuestion 是 1-4 题、
每题 2-4 项、每项 label+description、可 multiSelect、推荐项排第一并在 label 里标
「(Recommended)」;Codex 是"要动手前先给一次批准";ZCode 是计划卡上停下来等确认。
共同点:**问题与答案都进对话历史**,不是一次性弹窗。

## 三、真正缺的三样(要写的就是这三样)

**Q1|一只新工具 `ask_user`**(注册表 51 → 52,文档税见 §六)

```
ask_user(questions=[{
  "q": "宣传片用哪种模式做?",        # 问题本体
  "header": "制作模式",               # ≤12 字的短标,给卡片角标用
  "why": "我的推荐是模板模式:……",     # 推荐理由与代价,写给用户看的人话
  "options": [{"label": "...", "note": "..."}],   # 2-4 项,note 必填口径由工具描述教
  "multi": false,
}], note="这些定了我才好排步骤")     →  返回用户原话选了什么
```

三条契约红线:①`recommended` 不是字段而是**排在第一项 + label 里写「(推荐)」**,
因为"推荐"是模型的一句话,不该被界面当成结构化事实去显示一个真没有的标记;
②返回文本**逐字是用户选的那一项**(加一句「(用户自己补充:……)」如果有自由文本),
模型不许转述成"用户选了 A";③参数不合法(0 项、>4 项、note 全空)直接返回错误、
**一个框都不弹**,别为了一条坏调用把用户打断。

**Q2|一条与确认并列的提问通道**:`GuiUI.ask_user(questions, note) -> dict` +
Bridge 注入 `ui.ask_handler`(`gui_bridge.py:578` 旁边一行),事件 `ask_request`,
门面 `ask_reply(payload)`。**不复用 `_confirm_event`**:两码事共用一把锁,
以后"提问被确认框吃掉"这种 bug 查不动;各一条锁与各一个 Event,顺序仍是全局一次一个。

**Q3|前端那张卡**:`#askOverlay`(克隆 `.overlay` 那套尺寸与焦点处理,不新写一套样式语言),
渲染 `questions[i]` 的 header / q / why / options,分页「N / M」与「上一个」,
底部固定两条出口:「按推荐继续」和「我来补充(填进输入框)」;答完在聊天区留一行痕
(问题 + 你选的),因为那张卡关掉就没了,而**"我当时怎么答的"必须可回看**。

## 四、四条必须写死的口径(不许做假,也都不是一行代码能带过的)

1. **永不无限等**。现状值得记一笔:`_confirm_event.wait()`(`gui_bridge.py:2837`)
   **没有任何超时,也没有任何人在停止/关窗时把它叫醒** —— 全仓只有 `confirm_reply` 会 set 它。
   权限确认实践中一闪而过所以没炸,但"用户不想答、直接聊别的"是**正常动作**,
   照抄那条 wait 就是做一个会卡死产品的功能。所以:每问必带「按推荐继续」与
   「我来补充」两条出口;`request_stop` 与 `Bridge.close()` 必须叫醒提问等待,
   叫不醒就如实报「没等到你的回答,这一轮按未回答处理」,而不是假装问过。
   (顺手把确认框那条同样的口子补上,是本轮最便宜的一笔债。)
2. **答案进会话消息,问题也进**。工具调用与结果天然进 `session.messages`,
   所以聊天区那一行痕不是装饰,是留档的可视化;重启恢复会话时它得还在。
3. **节制**:`system_prompt.md` 新加第 16 条要写死"什么时候**不该**问"
   —— 一个选择可逆、代价说得清、用户上一句已经暗示过答案的,直接做并告诉他;
   一次最多 3 题;**不许把"我不知道"当成问题抛回给学生**。
   这条不写,功能会变成刷屏机器。
4. **子代理与网页版各自的态度要显式**:只读档(`explore/review/audit/testaudit/english`)
   默认**拿不到**这只工具(它的职责是查与报告,不是替用户做决定);领域档要不要给,
   是 §七 D1 的一部分。网页版按 `web_profile.py:207` 同一条路:要么整只不注册,
   要么自动按推荐并在回话里写「网页版没弹问题,按推荐做了 X」——
   **绝不允许静默卡住访客**。

## 五、刻意不做(参考了但这里不抄)

- 不做「不答就不让继续」的硬锁(截图那句"请回答必填问题"是提示,不是把输入框禁掉)。
- 不做多题表单式的必填校验、进度条、"已答 2/3"这类表单语言 —— 学生不是来填表的。
- 不做自由文本 + 附件 + 日期的复合表单(另一量级,且没有真实需求撑)。
- 不做"计划模式专属":任何时候都能问,但提示词只教它在**动手前的分叉点**问
  (与 `plan` 第 1 步之前问一次搭伴;每步都问就是刷屏)。
- 不给它开"替用户记住偏好"的口子:那属于长期记忆那条线,已另有工具(`memory`)。
