## 一、用户想要的是什么

"我现在手上到底有几件事在跑？"——这一句现在回答不了，因为线索分在四处：
①侧栏的会话列表（哪个会话在转圈）②当前会话的计划面板（只在**这一个**会话里有 plan）
③后台命令（`bash_status` 查得到，但没有一屏）④定时任务（`desktop_notify action=jobs` 逐任务报）。

再往前提速的是：v0.9.98 起 **worktree 工作副本**（W1）与「数据归属上卡」（W2）之后，
活儿真的会同时落在两个目录里，而"哪些是全局一份、哪些各工作区一份"才刚在 💾 面板上讲清楚。
Qoder 把这一层做成 **My Quests 看板**（Running / Action Required / Completed 三态，
多任务并行调度 + 分屏监控），ZCode 把它做成 goal 模式带里程碑校验。

## 三、真正的缺口（三件，按风险排）

### B1 · 一屏"在跑 / 等我 / 完成"的聚合（低风险，先做，且**先只读**）
- 一个新模块 `minicode/board.py`（**只聚合不重算**，与 `health.py` 同一条定位）：
  把四路的现成结论拼成三态：
  - **在跑**：running 会话（依 §二.4 核出来的真源）+ 后台命令；
  - **等你**：会话里有待答的 `ask_user` 卡、有正在等的确认框（v0.9.96 那条
    `abandon_pending` 的账正好给了"有没有人在等"的判据）、计划里卡住的步骤
    （`ready_steps` 为空但有 pending → 是被谁卡住）、验收没跑的步（配合验收方案 V1）；
  - **完成**：近期收敛的计划/任务（含定时任务上次结论），带时刻。
- 每一行都必须能追到一条真调用/真账（这条是他定死的规矩：**要真正能用的，不能只用于装饰**）；
  取不到就不出现，**不许画一个空的"暂无任务"占位来撑版面**。
- 只读：点每一行的行为 = 跳到那个会话 / 打开那个面板 / 把追问填进输入框
  （与活动面板那四段"点一下是真做事"同一条口径），看板自己不改变任何状态。

### B2 · 跨工作区维度（中风险，依赖 B1）
- W1（工作副本）+ W2（归属上卡）之后，"在跑"必须能区分**在哪个副本里跑**：
  按 `workspace` 分组，组头显示工作区名（`ws.display_name` 那份口径），
  全局一份的数据（课表/成绩/待办/心情）不进组，避免"两个副本里各数一遍同一份待办"。
- 这条最容易出的错是**把同一份全局账当成每个工作区一份**，正好是 W2 刚在 💾 面板
  上讲清的那件事 —— 复用它那份真相（`mydata.TABLE` 的 scope 字段），别自己再判一遍。

### B3 · 从看板派活（高风险，最后）
- Qoder 的板能新建/派发任务；这里要接的是"给某个会话追加一轮输入"，
  会撞上多会话并发的确认通道（**一条锁、一次一框**，v0.9.60 的设计）与
  `_TaggedUI` 标签队列。没想清楚"两个会话同时等你点"要怎么排之前不做。

## 四、必须写死的三条口径

1. **不新增一份"任务状态"落盘**：看板是四个现成来源的**视图**。一旦新开账本，
   就必须回答"会话被杀后这份账谁清"，并且要交个人数据四处登记税
   （`.gitignore` + `state_files.SHIP_NEVER` + `mydata.TABLE` + 打包清理）。
   第一版坚决不做持久化，只做一次现算（性能不够再谈缓存，缓存**不落盘**）。
2. **成本要说清**：`list_sessions` 是**逐行读 jsonl**（`:569` 那个循环），
   会话多起来时"扫全部"就是几十上百个文件 I/O。所以第一版明确设上限
   （最近 N 份 + 只读每份的头尾若干行），并在界面上说"只列最近 N 个会话"，
   不许悄悄截了还写"全部"。
3. **不谎报"在跑"**：拿不到确证就归到"没在跑/不知道"，并说清为什么（进程不在、
   留档没写、跨进程看不到）。这条和 `--live`、"没查成不等于没问题"是同一族口径。

## 五、刻意不做

- **不抄 Qoder 的分屏多会话同屏**（tiled layout）：那是窗口管理器级的工程，pywebview 这边
  一个窗口一套前端，做它是另一个量级；先解决"看得见有几件事在跑"。
- ~~**不做通知式"任务完成"弹窗**~~ → **一半已在 v0.9.104 做掉,另一半仍不做**。
  原话的理由是「注册一条新类别要走 `NOTIFY_KINDS`/`KIND_LABELS`/托盘菜单/白名单测试那一整条路」——
  那条路 v0.9.104 为**后台命令跑完**(新增 `background` 一类)已经走完了,所以成本不再是理由。
  仍然不做的是**看板自己那一句「某一步做完了」**:看板存在的意义就是「我自己看一眼」,而步骤完成的
  密度比一条长命令高一个量级(一步弹一条会把人淹掉,那种打扰没有回执价值)。后台命令正相反 ——
  它是「人走开了的一件长事」,跑完那一刻没人说才是问题。
- **不接"云端任务"**：项目边界是本地优先（`project-local-first-scope`），
  看板只读本机现成事实。
