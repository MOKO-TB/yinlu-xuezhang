## 一、为什么值得动这把锁(四扇它今天开不了的门)

1. **只会拦,不会改**:`run_hook` 的返回只有 `{ok, blocked, output, elapsed_ms}`(`minicode/hooks.py:119`)。pre 非零退出 = 拦截(`:119` `blocked = kind=="pre_tool" and not ok`)。想「把这条命令换成安全的那条」只能拒掉、让模型自己重试 —— 白花一步,而且模型未必改得对。这是 §6 #49b 的原话。
2. **人点头之前没有任何策略点**:`_execute` 的门序是 `gate.check` → REJECT 硬拒 / ASK 弹框(`minicode/agent.py:828-843`)。ASK 这条路只有 `ui.confirm_tool` 一个出口;REJECT 回给模型的是**「已阻止执行,请勿重试」**(`agent.py:831-833`)—— 模型手里没有"申请一次例外"的出口,这就是 #49d 那半条没做的根因。ZCode 把 `PermissionRequest` 单独做成一个事件,正是给这一格留的位置。
3. **「编辑后自动跑 lint/测试并回灌」今天做不出来**:两道死结 —— ①超时写死 10 秒(`hooks.py:28` `HOOK_TIMEOUT = 10`),真测试跑不完;②post 失败只能在结果尾部附一行(`agent.py:861-863`),**改不了结果本身**,模型看到的仍然是一句"文件已写好"。
   最硬的证据是这条已经有人手工替钩子干过活了:`_py_syntax_feedback`(`agent.py:1152` 起)把「写后 ast 自检、报错原文回灌」直接**编进代码**,注释里写明借鉴 aider。那是本该是一条默认钩子的一条规则 —— 这一层补上,它才有地方搬家。
4. **matcher 盖不住 shell**:`_matches` 只读 `args["path"]`(`hooks.py:72-81`),而 `bash` 的参数是 `command`。所以"只对 git 开头的命令跑一遍审计"今天**表达不出来**,而这恰恰是钩子最常见的用法。

**顺带一笔免费的**:`run_hook` 已经算了 `elapsed_ms` 并回吐(`hooks.py:120`),而 `_execute` 两处调用都没读过它(`agent.py:846`、`:861`)—— v0.9.114 观测线把每一步的实测毫秒都摆上了时间线,唯独钩子耗时是黑的。拿回来几乎不要钱。

## 四、要写的就这六件(按阶段,每件都能单独收口)

### P0 · H1|决策形状统一 + 允许改写

`run_hook` 的返回从 `{ok, blocked, output}` 扩成(缺省全部向后兼容):

```
{"ok", "blocked",
 "decision": "allow"|"ask"|"deny"|"continue",   # continue=不表态,照今天的流程走
 "output":   给模型看的话(仍是尾部封顶,截了几字要写明),
 "updated_input":  dict|None,                   # 仅 pre_tool 有意义
 "updated_output": str|None,                    # 仅 post_tool 有意义
 "context":  str|None,                          # 附加进本步结果,不改写原文
 "elapsed_ms": 实测, "ran": bool, "hook": "pre_tool"}
```

四条契约红线:

1. **改写点唯一,且在 `gate.check` 之前**。门永远只看最终真正执行的那份参数;改写完**必须重跑一次 `gate.check` 与 schema 校验**(钩子吐出非法参数不能直接喂 handler)。
   反过来的做法 —— 先判门再改写 —— 等于"用户点过头的内容"和"被执行的内容"是两回事,那是这批升级里唯一能做出真漏洞的姿势。
2. **钩子改不动红线**。清单原样抄过来即可:敏感目录(`~/.ssh`/`~/.aws`,`sandbox.py:52-60`)、disaster 命令(`permission.py:83`)、`.git` 写入(`permission.py:210-225`,本来就排在模式判断之前)、工作区内凭据(`sandbox.py:66-76`)。硬拒**根本不叫钩子**,也不给钩子表态的机会。
3. **改写三处留痕**:确认卡/步骤卡上一行「钩子把 X 改成 Y(原文在此)」、安全日志一行、回给模型的话里写明。**绝不允许静默改写。**
4. `on_error: "block"|"continue"`(**默认 block,即今天的 fail_closed**)。必须能改,因为钩子写坏一处(拼错的 matcher、命令不存在)的现成表现是**把所有工具调用全拦死,而用户完全看不出为什么**。

顺手补 matcher 两个字段:`command_prefix`(治第 §一.4 条,`bash` 从今天起可辨)与通用 `args_match: {参数名: 通配符}`;**不**引入 JS 正则(与现有 `fnmatch` 一种语法就够,两套语法迟早对不上)。
`timeout` 改为 per-entry(默认 10、**上限 120**,超上限按上限并在输出里写明被压回)—— 这一条不落地,P2 的 lint/test 闭环永远做不出来。

### P0 · H2|钩子耗时与失败进观测线(白拿的一笔)

- `elapsed_ms` 记进这一步的留档与时间线,口径与 v0.9.114 那条线一致:**实测优先,不拿 `ts` 秒级差补**。钩子耗时**不计入** `_step_ms`(那是 handler 全程,`:857-859` 注释钉着"确认框等待不算"),单列一行,别把两把尺并成一把。
- 同一只钩子连续失败 3 次 → 走 `findings` 立卡(与重复失败探测器同一把 `call_signature` 尺),文案不许说"我已停用了它" —— 停的从来不是钩子,用户配的东西只有他能改。

### P1 · H3|`permission_request`:弹框之前给一次策略点(同轮解开 #49d)

- 只在 `decision == ASK` 时叫,REJECT 永不叫(见 H1 第 2 条)。
- 输入:工具名、**改写后**的参数、`reason`/旁白(`self._narration`,`:171`)、以及**是哪条门触发的 ASK**(模式默认 / 越界路径 / 凭据 / 外部内容升级门 `ask_note`)。
- 输出 `allow|deny|continue`,`continue` = 照常弹框(默认,也意味着没配钩子的人行为逐字节不变)。
- **`allow` 只对本回合这一条生效、不落盘** —— 与 `approve_outside(session=True)` 不落盘同一条口径(`:843` 注释)。
- **两类 ASK 不接受机器代答**:①本轮接触过外部内容而升格的敏感动作(`permission.py:232-260` 的 M3 升级门)②凭据类。注入防御的最后一道是**人的眼睛**,把它变成钩子的 stdout 解析,等于给围栏装了个内部开关。这一条要写进 `SECURITY.md`。
- #49d 的另一半在这里补:硬拒时回给模型的话从「请勿重试」改成「这条路被红线挡着(说明是哪条)。要例外只能由用户改配置或项目白名单,你可以直接向用户说明需要什么权限」—— 给出口,不给绕过。

### P1 · H4|`session_start` / `user_prompt_submit` / `stop` 三个便宜点

落点都只有一个:`run_turn` 开头(`:140` 之前)、用户消息入会话处、`return` 那几处(`:174`、`:194`、`:196`)。

- 语义只做两件:**加 context**、**记审计**。
- **`user_prompt_submit` 不许改写用户原话** —— 留档里那条必须是他说过的字(与 `ask_user` 那条"答案逐字回填"同一哲学,见 `docs/roadmap-规划中途向用户提问.md` §三 Q1 契约红线②)。
- **`stop` 不许拦住本轮结束** —— 它能补一句上下文,不能否决停止。否则做出一把"用户按了停止而程序自己决定不停"的产品。
- 三个点都在无 UI 层,**不新增任何等待**(§6 #9 那条"永不无限等"的教训同样适用:等待卡不自动超时还挂在 #49e)。

### P2 · H5|`pre_compact`(便宜,一个落点)

`compaction` 的唯一入口就一处,压缩前给钩子一份将被摘要的消息尾巴:可**留档一份原样**、可往摘要提示里加料。语义与 `agent.py:780-806` 的自动压缩阈值不打架,压缩仍**当场回话**。

### P2 · H6|编辑后自动化闭环(H1+H2 拼出来的第一个真用例,不是新功能)

`post_tool` 命中 `write_file`/`edit_file` → 跑 lint/test → 非零退出用 **`updated_output`** 把失败原文回灌,让模型当场修。然后把 `_py_syntax_feedback` 那条硬编码降级成**内置默认钩子**(或保留为不可关的底线,§七 D5 之外再问一句),**别留两套真相** —— 这正是这件事最该防的退化形状。

### 明确不做(想过了,理由写在这)

- **http handler**:新开一条出站通道。`SECURITY.md:83-92` 已明说 `allow_network` 不是防火墙,再给钩子开 URL 就是给"读工作区内容 → 外发"修快速路。Claude 那边靠 `allowedHttpHookUrls` 才敢开,我们没有那层管控。
- **prompt / agent handler**:替用户花额度去跑一次模型。同 `docs/roadmap-MCP-resources-prompts.md` 里 sampling **不接**的判定,一条尺子。
- **工作区/项目级 hooks 文件**:通行证问题,`hooks.py:6-9` 的理由一个字都不变。
- **`subagent_start/stop`、`file_changed`、`cwd_changed`**:要先回答"钩子在谁的路上跑" —— 子代理已经剥掉了 `task/ask_user/export_trace`(`subagents.py:349`),而钩子跑在子线程里时的确认队列、耗时口径、findings 归类是另一整轮工程量。铺 30 个事件不是完善,是负债。
- **`PostToolUseFailure` 独立事件**:今天 `post_tool` 就能拿到失败结果,先不拆。

## 五、四条必须写死的口径(不许做假)

1. **没配钩子 = 零开销、零行为变化**。今天是真的:`_entry` 返 None、调用方直接跳过(`hooks.py:93-95`、`agent.py:1138`)。这条被新字段稀释的表现是「我一行钩子都没配,步骤卡上怎么多了一行」。所有新返回值都要能在"没跑过钩子"时**根本不产生**。
2. **钩子输出进模型上下文这件事本身是注入面**。它是本地命令的 stdout,按 provenance 的 `local` 级处理,**永远不得伪装成 user 角色消息**;长度封顶,截断要在正文里写明截了几字(项目既有口径)。并且文档必须明说:**钩子命令继承完整环境变量**(今天 `subprocess.run(shell=True)` 就是继承,而 config 里有供应商 Key)—— 提供 `env` 白名单/`clear_env` 是可选缓解,**别把它写成防线写成"你自己配的,这是你的决定"**。
3. **判定顺序钉死并写进测试**:红线 REJECT > 钩子 deny > 钩子 allow > 模式档位。任何"钩子放行"不得写入 `permissions.json`(那是另一条闸、另一种信任来源,sha256 内容点头是它的前提,`permspec.py:177-200`)。
4. **一次工具调用最多一次 pre、一次 post**,顺序变化要在卡片上讲得清。今天 pre 拦了就不画卡(`agent.py:846-847` 注释:"拒绝不该先画一张正在执行的卡"),升级后**改写要画卡且画的是改写后的** —— 这条口径翻脸比翻书快,必须落到测试里。

## 八、H1~H4+H6 落地后的十一条偏差(v0.9.115;读代码前先看这一节)

1. **"硬拒根本不叫钩子"实现成了什么**:字面做法(红线判定在钩子之后)与"改写必须发生在门之前"直接冲突 —— 参数没定稿就跑门,跑的是那份不会执行的参数。落地用的是 `hooks.matched()`:一个**不启动任何进程**的认领判定,配了钩子且认领这一步时才先只读跑一次 `gate.check` 只为拿 REJECT 这个判断,撞上红线连进程都不起(`agent.py::_matched_config_hook`)。代价是**没撞红线时门被跑两遍** —— `check()` 每次自清 `ask_note`/`project_allow_reason` 再返回,是纯判定,重复调用不产生第二次弹框、不写任何状态。**这条是实测出来的前提,不是假设:改天谁给 `check()` 加了副作用,这个双跑姿势就坏了,要改成"红线单独抽一个只读谓词"——那又会开出第二套红线判定,得先想清楚哪个更贵。**
2. **`updated_output` 是追加,不是替换**(与 Claude 的 `updatedToolOutput` 名字像而语义不同)。理由写进代码注释了:原结果被吞掉就是真没了,而"我把结果换成了别的"这种账本项目不写。要回灌的正文在 `_truncate` **之前** append,所以它可能被围栏一起包住(对 `web_crawl` 那类结果)——宁可把自家附注多标一层"外部内容",也不给一条外部命令开无上限的出口。
3. **只有结构化 JSON 才拿得到采纳权**:普通 stdout 照旧丢弃。两个原因 —— ①不改变没动过配置的人的行为(§五.1);②**只认"整段能解析成对象"这一种**,从半屏混排文本里猜哪一段是 JSON,等于让用户一次格式化失误变成一次静默的权限变化。所以钩子脚本 print 一行日志再 print JSON 是**不生效**的,要声明决策就得只输出那个对象。
4. **D4 只落了一半**:`hook_ms` 落档并出现在重启还原的时间线里(「用时 5s(钩子 0.4s)」),**实时步骤卡上没有** —— 那要多一条 UI 事件通道(gui_ui/gui_bridge/frontend 三处 + 前端冻结针),与本轮主题不同一条线,单独排。**没配钩子的人一律零变化**:门只跑一遍、留档不带 `hook_ms` 键、时间线那一格与升级前逐字节相同(测试 `test_no_hook_means_the_archive_gains_no_key` 钉的就是这条)。

5. **H3 落地时比本文多划了一条线**:`permission_request` 不接受代答的门从本文写的**两类**变成**三类** —— 凭据、外部内容升格,再加上**仓库 `.git`**。理由是它自己的门注释就写着"权限档位、项目白名单、本轮总是允许都不替它背书",与那两类同一种物种;而钩子读到的输入里正含这一步要做什么,它的输出又可能被刚抓来的外部内容影响 —— 把最后一道换成 stdout 的一个字,围栏就只剩纸。
6. **H3 与 pre/post 最大的一处不同:`on_error` 在这一类上完全不适用**。pre 的"没跑成"要按 `on_error` 决定拦不拦,permission_request 的"没跑成/超时/没写 decision"只有一个归宿:**照旧弹框问人**。一条坏掉的策略钩子既不配替人拒绝、更不配替人放行 —— 这里没有"失败即放行"也没有"失败即拦",只有"失败即交回给人"。判据是 `declared`(跑成且 allow/deny 说死了)。
7. **为了让上面那条判定不靠读中文文案**,`PermissionGate` 加了结构化字段 `ask_kind` 与助手 `_ask(kind, note)`,八条 ASK 出口逐条标来源(`outside_path`/`credential`/`sandbox_command`/`outside_command`/`script`/`git`/`external`/`mode`)。原先只有 `ask_note` 那份**给人看**的中文,拿它做安全判定就是分层指令文件 §四.1 拒绝过的那种假防线:改一个字,防线静默消失。
8. **`HARD_REJECT_NOTE` 文案改了**(收 §6 #49(d)):从"已阻止执行,请勿重试"改成"这一步没有执行,不要重试 + 这条路只有用户本人能放开 + 向用户说明你想做什么、被哪条红线挡住、需要什么权限 + **不要换一种写法绕过它**"。给的是说话的对象,不是绕过的通道。`tests/test_tool_outcome.py:51` 里那句旧原文没跟着改 —— 它只是拿来验 `is_failure` 的前缀,不是钉文案。

9. ~~**H4 只落了 `session_start` 与 `user_prompt_submit`**（用户点名这两个），`stop` 未做~~ —— **`stop` 已由 v0.9.151 补上，H4 三点齐了**。当时记下的两个顾虑，落地时各有一个**结构性**的答案（都不是靠小心）：
   - **「要挑 `run_turn` 里好几个 `return`，漏一个就是有时候不发」** → 没有逐个插，而是把 `run_turn` 拆成"外壳 + `_run_turn_body`"，`stop` 放在外壳的 **`finally`** 里。`_run_turn_body` 现在有 **8 个出口**（答完 / 撞步数上限 / 被停止 / 模型报错 / 四个预算与时限闸），逐个插必然漏一个；`finally` 保证恰好发一次，而且**它连"漏"这个可能都没有**。
   - **「『本轮不许结束』这类否决权一旦给出就收不回来」** → `finally` 里跑的东西**根本没有"否决"这个动作**，所以不是"我们决定不给它否决权"，而是**这一格拿不到否决权**。`hooks.run_hook` 里那三类非工具事件都把 `deny` 判成没生效并当场说出来（`hooks.py` 那段），`stop` 照旧。测试里专门有一支拿 `exit 2` 去撞，答复照样落地。
   - 余下三处偏差（只做加 context 没另开审计账、附话只活一次请求、非工具事件不许被 `tools`/`paths` 筛掉）**一个字都没变**，仍然成立。
   - 本文原写"加 context、记审计"两件事，实际**只做了加 context**，走的是 `_pending_prior` 那条**已有的一次性通道**（差评避让也住那里，两边**追加**、互不覆盖）。审计没另开一本账：这两个事件不是安全事件，塞进 `log_escalation` 会把那本账弄脏。
   - **那句附话只活到下一次请求为止**，不是 Claude 的 SessionStart 那种整段会话常驻。为什么不常驻：常驻就得写进 system prompt，而 `_refresh_clock` 会按天/按指令指纹重建 system —— 钩子那句一旦被重建掉，表现是"我配的话有时生效有时不生效"，比不生效难查十倍。这条差距写进 README 与《使用说明》，不假装等价。
   - 新立一条规矩：**非工具类事件不许被 `tools`/`paths` 筛掉**（`_matches` 里 `tool` 为空一律放行）。否则用户在那类钩子上写个 `tools` 就把它变成永不触发，而没人会说一句话。子代理不叫这三个事件，靠 `Agent(is_sub=True)` 这一只显式旗标，不靠"工具名带·前缀"那种间接特征。
