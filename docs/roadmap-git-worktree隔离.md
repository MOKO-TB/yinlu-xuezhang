## 一、用户想要的是什么

同一个仓库里同时做两件事:一边改 A 功能,一边查/改 B 功能,两边**互不踩文件**。
现在做不到的原因不是"子代理不够",而是**一个学长窗口只绑一个工作区**:
`Bridge.workspace` 是一个值(`gui_bridge.py:553`),切工作区走 `switch_to`/`cmd_workspace`,
换的是"这一窗口在哪个文件夹里干活"。并行的两路子代理**共享同一个工作区**,
所以硬规矩是"各路负责不同文件"(`subagents.py` 的工具描述里就写着)—— 这是同一个物理目录
内的分工,不是隔离。

## 三、真正的缺口(三处,按风险从低到高)

### W1 · 「同一项目的第二个副本」作为一个入口(低风险,先做)

不叫"worktree",叫**「再开一份工作副本」**:选一个 git 仓库 → 学长在**同级目录**建
`<项目>__<分支名>/`(`git worktree add --detach <path> <ref>` 或 `git -C ... worktree add -b <新分支>`),
把它当成一个普通工作区打开。落点:

- 新建 `minicode/worktree.py`(纯函数 + 一条 subprocess):**只做"问 git 要事实"和"生成一条要用户确认的命令"**,
  不自己偷偷建目录 —— 建/删目录是写操作,必须过 `bash` 那条确认框(复用现有权限链,不开第二条路);
- 面板入口:项目卡片(`sidebar` 的项目那一段)上加一行"这份工作副本从哪个分支来",
  数据出自 `git worktree list --porcelain`;
- 展示而非托管:`worktree.py` 只读地报"有几个副本、各在哪个分支、有没有未提交改动",
  **不提供删除**(删工作副本 = 删掉别人正在改的东西,这一轮不做)。

### W2 · 两个工作区并排跑(中风险,依赖 W1)

同一窗口左右两栏各绑一个工作区不现实(整条 UI 是"一窗一会话"的形状),但**多标签会话**已经是现成的:
`_runners` + 侧栏会话列表。缺的是三件小事实要说清:

1. **哪些数据跟着工作区走、哪些不跟着走** —— 现在 长期记忆分两份:本项目那份按工作区路径存
   (`mem_path(workspace)`,与用户级 `global_memory_path()` 并列),而 **课表/作息表/待办/提醒是
   全局一份**(`schedule.py:38` → `app_path(SCHEDULE_FILE)`)。所以两个副本会:记忆各自一份、
   课表共享一份。这不一定是错的(校园数据本来与代码仓库无关),但**必须写在界面上**,
   不能让用户以为副本是"完全独立的世界";
2. 会话列表要按工作区分组(§6 那条"工作区进阶"欠账正好一起做);
3. 停止/授权/额度都是会话级的,已无需改。

### W3 · 让子代理跨工作区派活(高风险,排在最后,也可能永远不做)

`task` 现在一路子代理继承 `ctx`(`dc_replace(ctx, ui=ui)`,v0.9.91 改的),工具集与沙箱根都只有**一份**。
要让"第 1 路在副本 A、第 2 路在副本 B"就得出:每路一份沙箱、一份权限门、一份确认队列、
一份实时表归属 —— 这已经不是加参数,是改子系统的形状。**建议先不做**,等 W1/W2 用起来
真出现"我要两边同时改同一个仓库的不同分支"的频次再说。

## 四、刻意不做 / 不要这样做

- **不做"自动 stash / 自动清理"**:用户没说就动他的工作副本,是最难追回的一类事故。
- **不在学长退出时删副本**:留着的副本对用户有价值(可以拿 IDE 继续改),而且"退出即删"= 我们替他做了决定。
- **不把 worktree 路径塞进 `workspaces.json` 之外再记一份**:一份事实一处真相,副本清单永远从 `git worktree list` 现读。
- **不新建第二份权限模型**:副本就是普通工作区,沙箱、白名单、凭据确认那套一模一样照用(见 §二最后一行:默认要重新批,这是对的)。
- **不要为了"看起来像 IDE"给每路子代理开独立终端/PTY**:交互式 PTY 那条 §6 #9 已经写明不做。
