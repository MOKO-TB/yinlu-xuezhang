### 阶段 1：增量更新路 2，manifest + updater

**问题**：现在只在馆藏库与浏览器内核身份未变时跳过两块数据。数据本身变化时仍然回到整包。

任务：

1. 设计稳定的 manifest schema：
   - 相对安装路径
   - 文件大小与 sha256
   - 新增、替换、删除三类
   - 版本与数据身份
   - 不记录本机绝对路径、不记录用户数据
2. 下载阶段先落到暂存目录，不直接覆盖安装树。
3. 应用阶段逐件校验：
   - 哈希一致的跳过
   - 需要替换的进入回滚目录
   - 缺失文件补齐
   - 删除清单只允许安装树内路径
4. 锁文件处理：
   - 运行中文件不覆盖
   - 使用“下次启动前替换”或独立 updater
   - 失败必须整体回滚，不能留下半新半旧
5. 保留现有信任边界：清单与安装包同源校验，不引入第三方镜像信任。

必须补的测试：

- manifest 路径穿越、绝对路径、重复路径一律拒绝。
- 全量哈希相等时不下载、不替换。
- 单件哈希失败时整次更新回滚。
- 删除清单不得删除安装树外文件。
- 更新中断后下次启动能识别完整的旧状态或完整的新状态，不能识别成混合状态。
- 老版本不读 manifest 时仍能正确回退到整包。

验收：

- 纯代码更新不再下载整包，实际流量接近 54 MiB 上限。
- 馆藏库或内核单独变化时只下载对应数据件，不再整包更新。
- 更新失败后旧版本仍可启动。
- 发布端、更新端、包内探针使用同一份 manifest 形状。

### 阶段 2：增量更新路 2b，拆分 PYZ

**问题**：`minicode.*` 被封在两个 24 MB 左右的 exe 容器里，代码改一行仍要替换整个 exe。

任务：

1. **先改冻结验证，再改容器**：
   - `check_frozen_version.py` 同时支持读取 PYZ 与新的 `minicode.zip`
   - 双读过渡期必须在包里证明两份来源逐字一致
2. 把 `minicode` 放入可替换的独立归档，启动时挂入 `sys.path`。
3. 保持现有导入路径、打包资源和数据路径不变。
4. 更新清单从“两个 exe”细化为“exe + 可替换代码归档 + 前端资源”。
5. 为损坏归档、归档缺失、版本不匹配提供明确降级或拒绝启动原因。

必须补的测试：

- 旧 PYZ 布局仍能通过冻结验证。
- 新布局的模块版本、文件哈希和包内运行结果一致。
- 归档损坏时不静默回退到旧代码冒充新版本。
- 前端资源与代码归档可以独立更新。

验收：

- 一轮约 2.4 MB 的真实变化，用户下载量进入 2 至 4 MB 量级。
- 包内运行、冻结针、e2e 和更新回滚全部通过。
- 不把第三方依赖拆成更新单元，避免一次更新变成数百个小文件。

### 阶段 3：馆藏 FTS 与标题归一化

**问题**：未命中、长查询和部分短查询仍可能走 1.31 GB 表的 `LIKE` 全表扫描。

任务：

1. 增加 `title_norm` 字段，统一处理：
   - 书名号
   - 全角/半角
   - 空格、连字符
   - 常见版本标记
2. 建立标题归一化索引。
3. 为 `books_fts` 设计 `unicode61` 分词迁移，保留旧库兼容与回滚。
4. 把迁移做成显式脚本，不在应用启动时静默重建大库。
5. 查询路径统一：
   - 精确归一化命中
   - FTS 命中
   - 最后才允许受控 `LIKE` 兜底
6. 用真实 1.31 GB 库做一次副本迁移计时、磁盘占用和结果对比。

验收：

- 未命中查询的 `EXPLAIN QUERY PLAN` 不再扫 `books` 全表。
- 原有书名、版次、副标题、作者查询结果不退化。
- 迁移可回滚，中断后不会留下半个可检索库。
- 冷启动不再因为馆藏统计或索引检查明显变慢。

### 阶段 4：`fetch_image` 网页图片抓取

**目标**：把网页里的真实图片安全地保存为工作区附件，供视觉模型或 OCR 使用。

任务：

1. 只接受 http/https URL，并接入现有出站网址策略。
2. 禁止 `file:`、data URL、内网地址、localhost、云元数据地址和重定向到私网的地址。
3. 限制重定向次数、响应大小、超时和图片类型。
4. 按真实 MIME 与文件头校验，不信任后缀。
5. 保存到工作区 `uploads/`，记录来源 URL、抓取时刻和 sha256。
6. 不自动把图片发给模型；由用户下一次操作决定使用视觉模型或 OCR。

验收：

- 正常图片可预览、可 OCR，历史会话可恢复附件标签。
- 私网、超大文件、HTML 冒充图片、无限重定向全部拒绝并说明原因。
- 出站策略为 deny 时根本不发请求。
- 网页内容不能通过图片 URL 绕过系统代理或敏感路径围栏。

### 阶段 5：嵌套子代理树形视图

**问题**：嵌套机制已存在，但前端仍把子代理当成平铺任务，默认关闭时也没有可视化入口。

任务：

1. 事件中补稳定的 `parent_lane`、`depth`、`root_task_id`。
2. 前端按根任务组织树形行，不按字符串标题猜父子关系。
3. 支持折叠、失败标记、耗时和产出数量。
4. 子代理默认关闭或没有嵌套时完全不渲染树，不影响现有单层界面。
5. 父级超时但后代仍在跑时，节点必须显示“父级已放弃等待，后代仍在运行”。

验收：

- 单层任务界面与当前逐字一致。
- 三层嵌套能正确显示父子关系。
- 父任务失败、子任务继续、子任务迟到报告三种状态不混淆。
- 跨会话事件不会串到另一个根任务。

### 阶段 6：交互式 PTY

**问题**：现在的后台 stdin 只适合一次性喂入，不是完整终端。

任务：

1. 新增 Windows ConPTY 执行通道，保留现有管道模式作为降级。
2. 接入 Job Object，确保关闭窗口、停止任务、超时能回收整棵进程树。
3. 终端输出保留 ANSI 基础序列并明确说明未支持的终端能力。
4. 不在 GUI 终端里新增绕过权限门的命令入口；所有命令仍走同一个权限门。
5. 禁止把用户终端输入写进模型上下文，除非用户明确采用为附件或引用。

验收：

- Python REPL、npm init、分页器这类程序能正常交互。
- Ctrl+C、窗口关闭、超时三种收手路径都能结束子进程树。
- 非 Windows 或 ConPTY 不可用时明确降级，不假装是 PTY。
- 现有 `bash`、`bash_input`、后台任务测试全绿。

### 阶段 7：MCP elicitation 表单

**问题**：当前收到 elicitation 请求时固定回 `decline`，不会向用户展示字段表单。

任务：

1. 支持 JSON Schema 的安全子集：
   - 字符串、数字、布尔、枚举
   - 少量必填字段
   - 不接受任意嵌套对象或代码执行
2. 把 schema 编译成现有 `ask_user` 提问卡。
3. 默认仍是拒绝；用户未回答时按 decline 处理。
4. 表单结果只回给当前 MCP 请求，不落盘、不进入长期记忆。
5. 网页版、`--mcp-serve` 和子代理默认不提供表单。

验收：

- 复杂或不支持的 schema 明确拒绝并说明原因。
- 表单数据不会出现在日志、会话留档或模型上下文中。
- 超时、关窗、MCP 断线都能让请求结束，不留下悬挂等待。

### 阶段 8：数据补齐与维护项

任务：

1. 按教务处正式通知补考试周、寒暑假、校运会、注册日。
2. 补校园地图口语别名、运动场坐标和 `not_buildings` 位置。
3. 把剩余 28 支 e2e 浏览器 fallback 逐支迁移到统一 helper。
4. 每迁移一支，就把测试上限减一，避免数量再次漂移。

验收：

- 所有校历日期都有来源、可信度和录入时间。
- 地图常见问法不再返回“没有这个标注”。
- e2e fallback 上限从 28 降到 0，真浏览器场景仍能跑。

## 六、跨阶段硬门槛

每个功能完成时必须同时满足：

1. 新行为有测试钉住，关闭开关后与旧行为逐字一致。
2. 新配置、新工具、新公开符号同步到 registry、PublicFacade、web profile 和冻结针。
3. 新落盘文件完成 `.gitignore`、`SHIP_NEVER`、`mydata.TABLE` 和安全文档四处登记。
4. 修改 GUI 时必须有真浏览器 e2e；只对源码文本做断言不算验证。
5. 修改运行时代码后先跑快车道，收口时跑完整全量、ruff、check_docs 和 diff check。
6. 更新类功能必须在包内运行一次，不能只验源码。
7. 任何“失败就降级”的路径都必须说明降级结果，不能把没做说成已做。

## 八、明确不做或暂缓

以下项目不进入当前版本计划：

- 云 Agent、远程工作区、SSH/WSL/Docker 执行体
- 整机电脑接管、屏幕点击自动化
- 语音输入
- MCP `authorization_code` 与 `sampling`
- bsdiff 二进制差分
- 代码签名服务或自建更新服务器
- 默认开启子代理嵌套
- 静默自动更新或自动安装

原因分别是信任边界、权限粒度、成本、可验证性或产品定位，不应为了追赶竞品数量而拆掉现有边界。

## 九、候选池，不排期

以下功能可以以后根据真实反馈加入，本轮不占主计划：

- 工作区语义代码索引：等真实出现“grep 和符号工具找不到”的反馈再做。
- best-of-N 多答案对比：需要明确额度消耗与用户点头机制。
- 本地多模态模型接入：先把网页图片抓取和现有视觉档做稳。
- 会话运行轨迹可视化回放：先复用现有 export trace，等排障需求增加。
- 数据件独立回滚中心：路 2 updater 落地后复用同一套 manifest，不另造格式。
