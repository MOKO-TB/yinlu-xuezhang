# 引路学长 v0.9.181

校园 AI 助手 / 编程引路智能体 —— 终端与桌面窗口双形态,内置校园模型,开箱即用。**完全本地运行**,不填 API Key 也能用。

## 这一版只管一件事：更新下载得更快

有同学说：升级已经只下 135 MB 了，**可还是慢**。这次先量了再改，没猜：

同一件 135 MB 的更新包，在这台机器上——

| 怎么下 | 实测速率 | 下完这件要 |
|---|---|---|
| 单连接，走 `api.github.com`（**App 以前优先这条**） | 0.03 MB/s | 65 分钟 |
| 单连接，走 `browser_download_url` | 0.28 MB/s | 8 分钟 |
| **四条连接一起拉** | 0.85 – 1.09 MB/s | **2 – 2.7 分钟** |

两个结论，第二个是意外：

1. **限速是按连接算的** —— 多开几条连接，同一件事快 3 倍以上。
2. **以前优先那条路，恰好是这里慢的那条。** 把它排成首选是有理由的（有些机器的 `github.com:443` 整台连不通，只有 API 通），这个理由仍然成立、这条默认也仍然保留；但代码里原来是"**失败**才退到下一条"，而**慢不是失败** —— 那条永远退不过去。

## 改了什么

- **先试再下**：下载前两条路线各拉 256 KB 比分快慢，**谁快用谁**。
- **一条连接只负责一段**：一件切四段并行下载，写进同一个临时文件的各自区间；下完**整件算一次 sha256**，核过了才改名叫"可以安装的包"。
- **中途取消不白下**：下次点下载是**四段一起接着下**，不是从头再来。

## 三件我们没做的事（说了免得你以为）

- **没有降低校验标准**。分段只是把"从哪儿拿字节"拆开，"能不能装"仍然由那一个 sha256 说了算；分段的半截文件中间可能有洞，所以一旦发现它不是本次下齐的，就**整份删掉重来**，绝不把两段不同来源的字节接在一起。
- **没有要求服务器支持新东西**。对方不认"范围请求"（带 Range 来也只给整件）就自动退回单连接原来的样子 —— 并发是优化，不是新前提。
- **没有把 GitHub 换成别的源**。字节仍来自你自己的发布页；这一版不做镜像、不接第三方加速域名。

一句话边界：这仍然**不是"只下载变化的内容"** —— 一轮真实变化约 1.7 MB 代码 + 0.67 MB 前端，剩下的 133 MB 是它们所在的容器；要下到 MB 级得把学长自己的代码从容器里拆出来，那是另一件事。
