# 引路学长 v0.9.182

校园 AI 助手 / 编程引路智能体 —— 终端与桌面窗口双形态,内置校园模型,开箱即用。**完全本地运行**,不填 API Key 也能用。

## 这一版只管一件事：升级下载得再快一档，并且修掉一处「下完了又被重下一遍」

有同学说：还是很慢，能不能**再多来几条线**。这次还是先量、再改。

同一件 135 MB 的更新包，在这台机器上——

| 怎么下 | 实测速率 | 下完这件要 |
|---|---|---|
| 单连接 | 0.025 – 0.056 MB/s | 40 – 90 分钟 |
| 四条连接（上一版） | 0.14 – 0.19 MB/s | 13 – 17 分钟 |
| 八条连接 | 0.26 – 0.42 MB/s | 6 – 9 分钟 |
| **十六条连接** | **0.42 MB/s** | **约 5.6 分钟** |
| 这一版实测一整件跑完 | 0.481 MB/s（含探测） | **4.9 分钟** |

限速是**按连接**算的，所以多开有账；上一版取 4 条太保守，这一版抬到 16 条。

量的过程中撞出两件谁都没料到的事：

1. **上一版那趟并发下载，下完之后没被当数。** 四条（现在是十六条）连接把整件拼齐以后，代码又走了一遍单连接的老路 —— 而那条路会从第 0 字节重写这个文件。于是**同一件被下两遍**；更糟的是第二遍一旦失败，已经下好的那一整件会被当成"半截不对"删掉，表现就是进度条走到 100%、然后一句「下载这一步炸了」，盘上一个文件都没有。这一版把它修好了：并发那趟拿到整件，就直接进校验，不再回头。
2. **挑哪条路，不能按单连接挑。** `api.github.com` 一条连接 0.056 MB/s 看着比 CDN 的 0.038 快，但八条连接时它只有 0.105，而 CDN 能到 0.423 —— **按单连接选出来的"快的那条"，恰恰是多开之后最慢的那条**。现在探测按四条并发试，探测的条件和使用它的条件一致。

另外把整件的切法也改了：以前一条连接跟到底的一大块（135 MB ÷ 16 = 8.9 MB），实测最后 10% 走了两分半 —— 十五条连接早空了，只剩一根 0.09 MB/s 的在收尾。现在按**每块至多 4 MB** 切开，谁先下完谁去领下一块，尾巴最多一块。

## 三件我们没做的事（说了你以为做了）

- **没有放松校验。** 分段只是把"从哪儿拿字节"拆开，"能不能装"仍然由那一个 sha256 说了算；分段的半截文件中间可能有洞，所以一旦发现它不是本次下齐的，就**整份删掉重来**，绝不把两段不同来源的字节接在一起。
- **没有让程序自己装、自己重启。** 仍然点两次：下载一次、运行安装一次。
- **没有把 `api.github.com` 从首选里去掉。** 有些机器的 `github.com:443` 整台连不通、只有 API 通（今天量第二轮时这台机器就复现了一次：CDN 那一条全部连接超时，而 API 仍然通）。它现在仍然是候选之一，只是**不再靠单连接的速度来决定用它**。

## 这一版对已经装好的机器意味着什么

**这一次升级仍然慢**：正在跑的 0.9.177–0.9.181 用的是它们自己那份下载代码，新的十六条连接在**要装的那个包里**，救不了正在下的这一次。速度从**装上这一版之后的下一次升级**开始。
