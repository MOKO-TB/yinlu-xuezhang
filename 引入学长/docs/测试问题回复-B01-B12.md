## 2. 逐条：现象 → 根因 → 怎么解决 → 怎么验证

### B01 AI 问答：知识库内/外问题 —— 通过，不算缺陷

- **实际结果**「没有出现幻觉」= 与预期「内准外拒、不编造」一致，这一项是**通过**，不是缺陷。
- **靠什么保证**（三层，缺一层都会漏）：
  1. **系统提示词写死服务边界**：`minicode/web_profile.py` 的 `PUBLIC_PROMPT` 明确「你只能使用校园知识库、图书馆馆藏、校园地图这三类数据回答」「条目里没有的就不说，宁可可查不到也不要编」。
  2. **知识库条目自带来源链接**：`search_knowledge` 命中的每条都带原文链接，回答必须附来源，编不出来源就答不了。
  3. **工具层面「查不到就说没有」**：地图索引里没有的地点，`campus.py` 的 `_miss_text()` 会返回「地图上没有这个标注」，而不是让模型猜位置。
- **语料规模**（老师若追问）：`kb/school-gzasc.json` 254 条校园问答、`kb/knowledge.json` 72 条成长知识库、`kb/wx-gzasc.json` 200 条公众号文章。

### B02 对话框无法滚动 —— 根因是 flex/grid 的默认最小高度

- **根因**：这是浏览器里最经典的一个坑。flex/grid 子项的 `min-height` 默认是 `auto`（不是 0），内容一多，子项就被内容撑高，**外层 `overflow:hidden` 又把超出的部分裁掉**——结果聊天区看起来「卡住、滚不动」，其实高度已经涨到视口之外了。
- **怎么解决**（v0.8.10）：
  - `frontend/index.html:97` 给 `.app` 网格加 `grid-template-rows:minmax(0,1fr)`（让行高可以被压缩）；
  - `frontend/index.html:145` 给 `.main` 加 `min-height:0`；
  - `frontend/index.html:166-170` 给 `.chat-wrap` / `#chat` 都加 `min-height:0`，`#chat` 保留 `overflow-y:auto`。
  三处一起改才生效——只改一处，中间那层还是会把高度撑开。
- **顺手做的**：`#chat` 加 `overscroll-behavior:contain`（滚到底不带动整页）+ 右下角「回到底部」按钮（`:172` `#scrollBtn`）。
- **怎么验证**：问一个长回答（比如「图书馆在哪 + 开放时间」），把窗口拉到最小，滚轮能上下滚、底部按钮能一键回底。

### B03 缺学校 logo

- **怎么解决**（v0.8.10）：侧栏品牌区 `.logo` 保留项目名「引路学长」+ 立方体图标，下面新增一行 `.school`（`index.html:111-113`、HTML 在 `:607`），放**校名横版 logo** `frontend/img/school.png`，高度 26px；深色主题下用 `filter:invert(1)` 自动反色，两种主题都清晰。
- **怎么验证**：打开界面，侧栏顶部同时有项目名和校名。

### B04 背景过于单调，不突出学校主体

- **怎么解决**（v0.8.10）：整页背景换成**肇庆校区黄昏航拍实拍图** `frontend/img/campus_dusk.jpg`（`index.html:78-82`，`background-size:cover` + `fixed`），所有面板改为半透明磨砂玻璃浮在照片上（设计令牌 `--glass` / `--blur`），形成「暮色玻璃」这套 UI，照片本身就是界面的一部分，不再是纯色。
- **怎么验证**：主页能直接看到校园建筑照片；切换深色/浅色主题，照片与玻璃面板都正常。

### B05 导入背景图后字体看不清 —— 属于 B04 的伴生问题

- **根因**：照片明暗不均，浅色文字压在亮部（天空、水面）上对比度不够。
- **怎么解决**（v0.8.10 / v0.8.17，两处配合）：
  1. **压背景、不压文字**：`index.html:87-90` 用 `body::before` 铺一层自上而下的深色渐变遮罩（`rgba(9,15,23,.34) → .20 → .46`），只降低背景照片亮度，不动文字；
  2. **给承载文字的面板实底**：消息气泡与「工作过程」卡片改成近不透明的实底（`.msg.assistant .body`、`.trace`、`.toolcard`，`:230-236`、`:283-289`），聊天区本身也给一层 `rgba(253,250,245,.55)` 磨砂底（`:170`），保证「玻璃透出照片」和「字看得清」同时成立。
- **怎么验证**：深色/浅色两套主题下，把消息区拉到天空最亮的位置，正文仍是清晰的黑字/白字。

### B06 地图功能不完善（问哪栋楼地图不显示）

- **根因**：v0.8.17 之前**根本没有地图模块**，回答位置只能给文字。
- **怎么解决**（v0.8.17 整块新建）：
  - **后端数据与工具**：新增 `minicode/campus.py` + 5 个地图工具（`registry.py:273-364`）：`map_find_place`（问「XX 在哪」→ 框出该楼并显示单栋标注图）、`map_show_list`（「学校有哪些楼/食堂」）、`map_highlight_building`（一次框多处）、`map_drop_pin`（钉一个点）、`map_clear`。
  - **问哪栋就发给用户**：工具命中后通过 `ctx.ui.push("map", …)` 推事件，前端 `map.js` 的 `apply()` 收到后**自动打开地图面板**并框选、缩放到那栋楼，同时弹出详情卡（建筑名 / 面积 / 邻近建筑）。
  - **关键设计**：同一栋楼有歧义时不猜——「A~E 栋」在地图上是两栋楼（学思苑X 与 集贤苑X座），工具返回 `ambiguous`，把候选**全摆出来让用户点**（`map_find_place` 的 `ask` 分支）。
  - **数据来源**：交付侧脚本生成的索引 `frontend/campus-index.json`（**36 处建筑 + 203 条学生俗称**），工具是查索引，不是模型现编。
  - 这 5 个工具都标了 `read_only=True`，理由是它们只画界面、不碰文件——否则框一栋楼就要弹一次权限确认。
- **怎么验证**：问「图书馆在哪」「E栋在哪」「学校有哪些食堂」，地图面板自动打开并高亮；问不存在的地点，回复「地图上没有这个标注」。

### B07 思考过程不能全部折叠

- **怎么解决**（v0.8.17）：把「思考 + 工具调用」收进一个可折叠的「工作过程」区（`.trace`，CSS 在 `index.html:289-300`），并且**不是靠用户手点**：
  - 默认折叠；一旦触发 `text_delta`（正文开始输出）就调 `foldAllTraces()`（`:1057-1067`）把聊天区里所有展开的过程区收起，`finish_stream` 再收一次；
  - 收起后只留一行摘要，例如「工作过程 · 1 个工具调用 · 思考 3 秒」；
  - 用户如果**自己点开**过某个过程区，会打 `dataset.touched` 标记，自动折叠就跳过它，不跟用户操作打架。
- **怎么验证**：问一个需要调工具的问题，最终答案出现时过程区自动收成一行，点标题行能重新展开。

### B08 对话进行中无法新建任务

- **根因**：老逻辑是 `if (!busy) new_task()`——任务跑着直接不给点。
- **怎么解决**（v0.8.17）：**每个会话一个 `SessionRunner`（各自一套 Agent/Session，跑在独立线程里）**，所以「新建任务」不需要等谁结束。`gui_bridge.py:518-532` 的 `new_task()` 直接 `open_session()` 开一个干净会话，**原会话转后台继续跑**，并推一条提示「N 个任务在后台继续运行（点左侧会话可切回去看）」；前端 `index.html:1382-1389` 去掉 busy 拦截，改成先 toast「正在停止当前任务并新建…」再新建。
- **怎么验证**：提一个长问题，等它开始输出时点「＋ 新建任务」，聊天区清空、侧栏原会话带转圈标记继续运行（回归测试 `tests/test_gui_bridge.py::test_new_task_keeps_previous_run_in_background`）。

### B09 新建完任务后回不到历史任务继续问答

- **怎么解决**（v0.8.17）：
  - 「新建任务」**不动旧会话的留档**：侧栏「历史会话」列全部会话（`refresh_sessions` → `_push_sessions`，每条显示首句 / 时间 / 消息条数 / 是否运行中）；
  - 点侧栏任一条就 `resume_session(index)`（`gui_bridge.py:613-634`）：如果那条会话**正在后台跑**，直接接上它当前的内存上下文（`_runner_for_log` + `switch_to`），不打断；否则从 jsonl 留档恢复，并回放全部历史消息。
  - 也就是说，切换会话是「换视角」，不是「重开」——原任务照跑，切回去就能看到最新进度。
- **怎么验证**：新建任务后再点回上一条会话，能看到完整历史且能继续追问（回归测试 `::test_resume_running_session_attaches_without_interrupt`）。

### B10 返回历史对话需要点确认，太麻烦

- **根因**：老代码点历史会话会先弹「恢复该会话并替换当前对话？」，要再点一次确定。
- **怎么解决**（v0.8.17）：删掉这一步——`index.html:1311-1317` 点会话条目直接调 `resume_session`，不再弹窗。**确认框只保留在真正有副作用的操作上**：删除会话（`appConfirm('删除该会话记录?')`）和权限确认。切换会话不丢东西（见 B09），所以不需要确认。
- **怎么验证**：点任意一条历史会话，一次点击即切回，无任何弹窗。

### B11 沙箱开启/关闭的弹窗挡住发送按钮

- **根因**：切换沙箱后会弹一条提示（toast）说明沙箱状态，而 toast 原来是 `position:fixed; right:16px; bottom:16px`——**正好压在右下角的发送按钮上**；连点几次还会叠成一片。
- **怎么解决**（v0.8.17，`index.html:428`、`825-838`）：
  1. **挪位置**：`.toasts` 的 `bottom` 从 `16px` 提到 `108px`，抬到输入框上方（底部输入区高度约 90px）；
  2. **去重**：同一条提示重复出现只重置 5 秒计时、不再叠一条（判断 `dataset.msg`），连点也不会糊满屏幕；
  3. 沙箱开关本身在顶栏（`:619`），与输入区物理分离，点击切换后按钮文案变为「🛡 沙箱开 / 关」。
- **怎么验证**：反复切换沙箱，提示出现在输入框上方，发送按钮始终可点。

## 3. B12（唯一未修）：地图状态在开启新一轮对话后仍然残留

- **现象**：用过地图后点「＋ 新建任务」开了新会话，**地图面板还开着、上一次的高亮框/图钉/搜索词/列表都还在**。预期是新会话开始后地图回到干净状态。
- **根因**（已定位到具体行）：新建任务会推一个 `cleared` 事件，前端 `index.html:1229-1237` 的 `case "cleared"` 只重置了聊天区（`renderHome()`、清 `cur/lastTool/lastTraceTurn`、`setBusy(false)`），**没有碰地图**；而地图自身的状态（`boxes` / `pins` / `activeCat` / 搜索框 / 详情卡 / 列表）在 `map.js` 里是模块级变量，跨会话一直保留。
- **改法**（两步，约 10 行）：
  1. `frontend/map.js` 里加一个 `reset()`，清状态但**不打开面板**——注意不能复用 `apply({op:'clear'})`，因为 `apply()` 第一行就是 `openPanel()`，会反手把地图又弹开：

     ```js
     function reset() {
       if (!svg) return;                     // 索引还没加载就不用清
       boxes = []; pins = []; activeCat = "";
       closeLightbox();
       $("mapSearch").value = ""; $("mapSearchInfo").textContent = "";
       renderCard([]); renderNotice(null);
       $("mapList").style.display = "none";
       renderLegend(); drawBoxes(); fitAll();
     }
     ```

     并在文件末尾的 `window.CampusMap = { … }` 里把 `reset` 导出。
  2. `frontend/index.html` 的 `case "cleared":` 里加一行（顺手在 `case "resumed":` 里也加，切会话同理）：

     ```js
     if (window.CampusMap) { window.CampusMap.reset(); window.CampusMap.close(); }
     ```

- **答辩口径**：这一项是**状态归属**问题——地图状态原来是全局的单例状态，应该跟着会话走。短期按上面在会话切换时重置；更彻底的做法是把地图状态按 `session key` 分开存（`Map<sessionKey, state>`），切回旧会话时恢复它自己的标注。
- **验证**：问「图书馆在哪」→ 地图打开并高亮 → 点「＋ 新建任务」→ 地图收起且无残留标记；切回上一条会话，重新提问能正常高亮。

## 4. 老师可能追问的点（先背这几句）

| 追问 | 回答要点 |
| --- | --- |
| 滚动为什么要写 `min-height:0`？ | flex/grid 子项的最小高度默认是 `auto`，会被内容撑高；父级又 `overflow:hidden`，溢出部分被裁掉，里面那层就没有可滚动高度了。必须在网格行（`minmax(0,1fr)`）和每一层 flex 容器上都显式压到 0。 |
| 凭什么说 AI 不编造？ | 三层：提示词写死服务边界 + 知识库命中必附来源链接 + 工具层「索引里没有就如实说没有」。模型想编也没有可引用的来源可挂。 |
| 新建任务为什么不用等当前任务结束？ | 每个会话一个 `SessionRunner`（独立 Agent + 独立线程 + 独立 jsonl 留档），`new_task` 只是 `open_session()`，老会话转后台跑；`resume_session` 能接上后台运行中的内存上下文，所以切来切去都不打断。 |
| 地图数据是模型编的吗？ | 不是。是交付侧脚本 `build_index.py` 生成的 `campus-index.json`（36 处建筑 + 203 条学生俗称），工具查索引、按坐标画框；没标注的地点直接答「没有这个标注」。 |
| B11 那个提示为什么会挡住按钮？ | 提示（toast）原来定位在右下角 `bottom:16px`，正好压在发送按钮上；改成 `bottom:108px` 抬到输入区上方，并加了同文案去重，避免连点叠满屏。 |
| 还有没有别的已知缺口？ | 有，见 `WEB.md §7` 与 `HANDOFF.md §6`：SSE 断线不补发、`web-sessions/` 无保留策略、会话切换按序号定位（并发落盘时可能错位，计划改成回传文件名）、子代理并行与计划依赖图未做。 |
