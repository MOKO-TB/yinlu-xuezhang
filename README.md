# 引路学长

一个运行在 Windows 桌面的编程引路智能体——**图形界面**里交任务,它自己读代码、改文件、跑命令,直到把事情做完;像学长带学弟一样,动手前讲思路,关键处给理由。附赠同核引擎的终端版。

## 功能

- **桌面 GUI**:玻璃拟态风(**浅色=校园日景航拍、深色=同一校园的暮色航拍**,切主题即换景;侧栏/顶栏/气泡/工具卡都是磨砂玻璃层),深色/浅色一键切换;会话列表、Markdown 流式对话;**思考与工具调用收成一条可折叠的「工作过程」**(最终回复开始时自动收起,点标题行展开回看);**划词即弹「复制选区」**,消息右键有原生菜单(撤销/剪切/复制/粘贴/全选),Ctrl+C/V/X/A 正常可用
- **后台任务**:新建任务 / 切换会话都**不会打断**正在跑的任务——每个会话有自己的运行器(独立 Agent 与会话上下文),旧任务转后台继续跑完;侧栏对应会话显示转圈与「运行中」,点它即可切回去看实时进度(模型、MCP 连接、沙箱策略在会话间共享,多开一个会话不会重复起进程)
- **内置校园模型,开箱即用**:固定使用广州应用科技学院内网模型服务(`deepseek-v4-flash`),不需要填 API Key,界面也不提供模型切换入口(顶栏模型标识只展示;内网地址与 Key 都不下发前端)。**模型的上下文窗口与「是否支持视觉」由程序启动时自动向服务探测**(结论缓存一周),任务面板标签与压缩触发阈值据此自动对齐 —— 学校换模型/换网关不必改代码
- **工作区(自己选文件夹)**:顶栏「📁 工作区」胶囊点开就能挑一个文件夹当 Agent 的工作台——读写围栏、附件 `uploads/`、计划 `plans/`、长期记忆 `memory/` 全部落在那个文件夹里;弹窗列出当前/默认与最近用过的 8 个(可一键移出列表,只动记录不删文件夹),「选择文件夹…」走系统原生对话框。CLI 用 `/workspace <路径>` 或启动参数 `--workspace` 拿到同一份记忆(详见「工作区」一节)
- **沙箱边界**:工作区内的路径直接放行、工作区外逐次确认、`~/.yinluxs` `~/.ssh` 等敏感目录永远拒之门外;还能禁网命令、加自定义禁配规则、卡命令超时;GUI 顶栏一键开关(详见「沙箱」一节)
- **附件上传**:聊天框 📎 选文件/图片,自动复制进工作区 `uploads/` 并把路径注入消息;图片按长边 1536 / 1MB 自动压缩,`vision: true` 时以 base64 直接发给视觉模型
- **本地知识库检索**:`kb/` 目录放 JSON 资料库(校园通知、经验库等,自带 credibility 可信度分级与来源网址),`search_knowledge` 工具按 中文 2-gram 打分检索(标题×3+标签×2+正文×1),回答引用时输出来源网址供用户核实,非 A 级数据强制标注"未经核实"
- **图书馆馆藏查询(离线全库)**:`library_search` 直接查本地 SQLite 馆藏库(133 万条 OPAC 书目,毫秒级),返回书名/作者/出版社/索书号/中图法/馆藏册数与馆藏地,并自动把中图法大类映射成楼层。**查询会自动逐级放宽**:`《C程序设计》`、`C语言程序设计（第5版）`、`高等数学（上）`、`三体：地球往事` 这类带书名号/版次标注/副标题的问法都能命中(以前会漏检并误报"没有这一本书"),且一次检索最多只走一次全表 LIKE,不会因多试几级而变慢
- **SKILL.md 技能系统**:`skills/` 目录放技能(带 name/description 的 SKILL.md),自动注入系统提示词,模型用 `use_skill` 工具按需读取全文;内置 git-commit / python-testing / code-review 三个示例
- **权限确认**:写文件(带预览)、编辑(带 diff)、执行命令先弹窗确认,可选"本轮总是允许"或切"自动放行"
- **安全兜底**:`rm -rf /`、`format c:`、fork 炸弹等灾难性命令硬拒绝;文件工具拒绝越出工作区
- **`/undo` 回滚**(CLI):写前快照,可连续撤销
- **上下文自动压缩**:token 估算接近窗口上限时,把早期对话折叠成摘要(按完整轮切分)
- **会话持久化**:每轮写入 `sessions/*.jsonl`;GUI 侧栏一键恢复,CLI `/resume`
- **桌面提醒(v0.9.25)**:主动推送(今日简报、课前 20 分钟、今天第一节课、临期/逾期待办、校历倒计时、官网新通知、新版本)**除了聊天栏顶部那条提示栏,同时弹一条 Windows 桌面通知**——窗口最小化在托盘里也能收到,不会再出现"人不在窗口前 = 提醒没发生"。正文**只复用聊天里已有的那行文字**,缺字段就整条不发,绝不为了"通知看着饱满"编课名或时间;托盘菜单里有「桌面提醒」总开关(打勾状态实时)和「测试一条桌面通知」;对话里也能说「提醒直接弹桌面」「别弹通知」「看不到通知」,走 `desktop_notify` 工具(status / on / off / test,可只动一类)。**两条默认克制**:窗口正在前景有焦点时不重复弹(那行字本来就读得到)、同一条内容 ~90 秒内只响一次;拿不准是否在前景时按"不在前景"处理(宁可多弹,不能把"快上课了"悄悄吃掉)。偏好落 `notify-pref.json`(坏文件回落默认全开,只读目录写不进去会如实回话)。**通道是 Windows 自己的 toast**(借系统自带的 PowerShell 5.1 走 WinRT,零新依赖;正文只经环境变量交付、不进命令行),第一次弹之前会自动在当前用户下登记应用身份,通知里就有中文名「引路学长」和图标(显示名要写在那坨注册表键的**默认值**上、图标路径必须是 `file:///` 形式,裸路径会被静默丢掉;而 Windows **第一次见到某个身份就把名字和图标缓存下来**,之后再改注册表刷不回来——所以登记一定发生在第一条通知之前,身份串也为此换过一次);旧的托盘气球只作回落,**且永远标着「未验证」—— Windows 11 根本不显示气球**,两条通道都不通时直说「都没发出去」并指向 `tray.log`,绝不假装已弹。**点通知直达(v0.9.72)**:toast 带协议激活属性 —— 点那条 Windows 通知,窗口弹回前台,课前/简报/待办/校历类提醒直接落到课表面板、心情周报落到心情面板(没有对应面板的类别只弹回窗口);实现是 `yinlu:` 协议注册(HKCU 指向 GUI exe,写完读回核对,安装版便携版一致)+ 激活监听(127.0.0.1,端口落 `activate-port.json`)做单实例交接 —— `--activate` 的第二进程先 POST 交接、送达即退绝不双开,没人在跑才自己启动并首屏落面板;协议没注册成功就不给激活属性,**不发点了没反应的空激活**
- **开机自启 + 补发错过的提醒(v0.9.26)**:托盘右键菜单多了「开机自动启动」打勾项,对话里直接说「开机自动启动学长」「别开机就启动」也行(`desktop_notify` 的 `startup_on` / `startup_off`)。实现是**在当前用户的「启动」文件夹里放一个快捷方式**——不写注册表 Run 键、不要管理员权限,你自己看得见、也删得掉;建完会**读回快捷方式指向核对**,指向不是本应用就不说「已开启」,关的时候更**绝不动别人的文件**(同名快捷方式指向别处只报告、不删除)。自启带的参数是 `--background`:启动后直接收进托盘;而托盘图标万一没建成,**照旧把窗口显示出来**——宁可多一个窗口,不能留一个"进程在跑但界面永远叫不出来"的隐形进程。补发解决的是同一件事的两头:课前提醒"今天弹过哪几条"原来只记在内存里,一重启就清空,于是**错过的那条永远不补、弹过的那条又会再弹一次**;现在落成 `pushed-today.json`(按天滚动、最多 200 条),启动后第一轮补两样——① 今天从没推过今日简报就补一条(早上没开机,下午打开也看得到今天几节课、要不要带伞);② 有节课**已经开课、且还在 60 分钟内**且没提醒过,补一条「错过的提醒:高等数学 08:00 已开课(现在 08:52,过了约 52 分钟)· 教室 B101」,**只给最近的一节**(一早上错过三节不会连着弹三条刷屏),而且它和到点提醒**共用同一把去重键**——先弹了"快上课了"就不会再补这条,反过来也一样。文案照旧只用真实字段:课表里没写钟点的课不定时、没写教室就不提教室,课表**没有结束时间**所以绝不宣称"这节课还在上",只说"已开课约 N 分钟"。账本写不进(只读目录、装进 Program Files)时退回内存集并**如实说没记住**:本次运行不会再重复弹,重启后可能再弹一次,不假装已经落了盘
- **空闲时段看板(v0.9.27)**:「我这周什么时候有空」终于有了一份**算出来**的答案——课表面板「本周」每天的格子里,课程下面列**空档时段**,再把当天要交的待办(⚑)和校历安排叠在同一列;点某一天下钻看那天空档的起止与「这天要交/校历安排」,退回到本周不丢位置。对话里问也走同一条路(`schedule` 工具的 `action=free`,支持某天/本周/下周),提示词每轮注入「本周空档(学长算好的,不是心算)」。**空档有两档口径,取决于本机有没有作息表**:没填时只说「第 3-4 节没课」并明确标「只按节次」——课表里没有下课时刻,所以**绝不编钟点**;点「填作息表」把教务处那张表的逐节起止录一次(存本机 `period-times.json`,只认从第 1 节起的连续段,断一节就退回按节次而不是猜下去),空档立刻升级成「10:00~11:40」,还能「不填了」退回。**三条不算错的口径是硬规矩**:那天不在学期内(开学前/假期)不等于"整天空着",一律不报空闲;某节课没写节次的那天**一条空档都不报**,直说「算不准」请你补节次(那门课可能正落在你以为空着的那几节里);没填作息表时只在**已排课的首尾之间**找空档,不宣称"最后一节之后还空着"。面板、工具、注入提示词共用 `free_slots` 这一份算法,前端**禁止自己再算一遍**(否则会冒出第二个版本的"有空")
- **到点提醒器(v0.9.29)**:「提前 20 分钟催我」不再只属于上课 —— `reminder` 记的待办只要**同时**有日期和钟点(「10月8日17:00前交」「周五下午5点报名」),就走课前提醒那条 5 分钟细轮询:到点前 20 分钟催一次,错过了还在 60 分钟窗口内则开机补一条,和「快上课了」共用同一份按天账本与同一个去重键(催过就不再补,改了截止时间会自动重新催一次)。**口径跟课表一样硬**:只有日期的事项仍按天催,绝不把「10-08」读成「10-08 的某个下午」;钟点认不准也照样丢掉 —— 「3点」没有上/下午就没有唯一答案,猜错等于差 12 小时,宁可只按天催。今日简报里「今天截止」那条会带上 17:00,明细列表则每条都带上你记下的钟点;同一天到期的事项**只报最紧的一条**,不刷屏
- **循环待办(v0.9.56)**:「每周三交周记」「每 3 天背一次单词」这类事记一次就够了 —— `reminder` 支持 `repeat`(只认「每周」与「每N天」),配一个能确定的具体日期作锚点(`anchor`)。**存盘的日期永远是"下一次"**:错过且补发窗口也关了的那一班,由 5 分钟细轮询自动滚到下一次(带 `projected` 与 `anchor`,照校历 `repeat:"yearly"` 的先例),所以电脑三天没开,开机也只会得到"下一个该出现的那次",**不会补出三条上周的旧账**。做完一次说「r 几完成了」,它记下这一次并**自动排下一次**(整个循环不停;要停就 delete)—— 完成后旧的那条自然不再催,新的一次到点照常催。三条诚实边界:**①未来班次照常催、过去班次绝不补发**(规则是你亲口定的,推出来的未来一次是功能本身;但"按循环补发历史"就是替你编考勤);**②循环规则必须配确凿锚点日期** —— 光说「每周」给不出日期,就按一次性提醒记下并说明,日期确认后删掉重加;**③「每月」不认**(大小月天数不一样,硬转 30 天就是编),「每两周」要说成「每 14 天」。同一轮里,定时任务底座(v0.9.42 的 `jobs.py`)也接上了两条后台心跳(`proactive._run_due_jobs`):到期的周期任务跑一次、记一次账,handler 异常也算"跑过这一班"(宁可这一期不发,不要每 5 分钟重试刷屏);A4 的周报两件按方案排在下一轮
- **周报两件(v0.9.57)**:定时任务表上的头两个真任务,都是**只说不做**——推一条带「追问」的通知,做不做由你把追问发回来才动,学长**绝不自动调模型、绝不自动爬**(那会花你的 Key 额度)。**每周心情回顾**(周日 20:00 后的第一轮):回读 `mood.weekly_review` 同一份真相——这周你记了什么、平均几分、有没有低到两分以下的日子;**一周一条没记就整条不发**,"你什么都没记"的通知是压力不是帮助,这是情绪模块"不做打卡"口径的延伸。**知识库缺口周报**(周五 18:00 后的第一轮):聚合 `kb-gaps.jsonl` 最近 7 天检索没命中的问法(`growth.gap_digest` 按 `normalize_query` 归组变体、数**不同日期**不数行数——旧账本里的同日重复不会虚报"出现 N 天"),top 5 摆给你看;补语料是显式动作,不管补不补,"库里缺什么"从维护者的直觉变成一行行可看的账。两类都进通知开关表(`review`/`gaps`,托盘右键→桌面提醒里按类别关);节奏刻意错开(周日晚上/周五傍晚),`jobs.py` 的 weekly 到期口径是"当天+到点",机器整晚没开这一班就跳过——"宁可少跑一次"的下周自然再来
- **.ics 兜底导出(v0.9.58,A5 半件)**:「把课表导进系统日历」从此是一条内置工具(`export_ics`)——在工作区生成一份「引路学长日历.ics」(课表 + 待办截止 + 校历一起),双击导进 Windows 日历/Outlook,或发到手机用「日历」App 打开;到点响的是**系统**,学长没在跑、电脑没开机也一样 —— 这是比开机自启更彻底的提醒兜底(v0.9.42 方案 §A5)。格式是手写的 RFC 5545(纯标准库零依赖):CRLF 行尾、75 **字节**折行(中文不劈开多字节)、TEXT 转义、VEVENT 带 DTSTAMP 与 VALARM;**UID 按"种类|标题|首次时刻|RRULE"确定性生成,重复导出再导入是更新不是堆重**。三条诚实边界:①课的钟点只认课表+作息表算出来的事实(`schedule.row_clock` 新公开口,含节次连续段校验与 start_time 反查),没填作息表的课**降级成全天事件**并在回话里点名哪几门、怎么补——绝不编一个 45 分钟;②校历里 `repeat:"yearly"` 的投影日子(按往年月日推的,学校还没通知)**一律不导**——写进系统日历就成了"每年照着过"的事实,与 `calendar_alerts` 过滤投影同一口径;③连日期都没有的待办跳过并报数。周次断档(如 1-2,4-5 周)拆成两个 RRULE 段,不假装第 3 周连上;网页版排除此工具(访客不该能在服务器工作区落文件)

- **信号回灌**(v0.9.39,`config.json` 的 `feedback_recall`,默认开):已经记下来的东西回头要真的改变行为。**①反复搜空**——同一个查询词在可见对话里连着空手,第 3 次起工具回话末尾附一行「×3 未命中 + 下一步怎么办」,右侧监控栏那一行从第 2 次起标「×N 未命中」(两处数字出自**同一次扫描**,不会各说各话);一次任务里换关键词补搜**不算**,那是正常检索。**②差评避让**——这次的问题若与最近 30 天里某条 👎 属同一类(判定接长期记忆去重那份 2-gram 口径:整体 ≥0.75 或较短一条被覆盖 ≥0.85,够不到就当没这回事),下一次请求里会给模型一句**系统侧先验**:换种方式答、先给依据与来源。它**不会**跟你说"你上次点了不满意"(那是把私下的一次点击当众复述),先验也**不进会话留档**,只在那一次请求里存在、用完即清。关掉开关,发给模型的消息与工具回话与开之前**逐字一致**(有测试钉着)。数据都在已有的 `message-feedback.jsonl` 与 `kb-gaps.jsonl` 里,**这一轮没新增任何落盘文件**
- **模型层收口**(v0.9.40):模型"看到的东西"这一层补了四个口子。**①时钟**——日期与课表是建会话时烧进 system prompt 的,而本应用是托盘常驻的:进程连着开三天,它会照第一天的日子念三天。现在每个回合开始前对一次表,**跨天了才**把提示词重算一遍(走 `build_system_prompt` 同一个函数,不出现第二份时间来源;一天至多破一次 KV Cache),并说一句「已跨天,日期与课表已刷新」。**②压缩**——超长历史折叠成摘要时从「保尾丢头」改成**留头 + 留尾**(总预算 40000 字不变),摘要提示词按校园场景重写:任务目标 / 改过哪些文件 / **日期·课名·地点·待办·来源网址** / 关键决定 / 下一步。**③尺子**——压缩阈值以前只数消息,而每次请求实际还带着 40 来个工具的 JSON Schema(几千 token),于是面板说"还早"它却突然压;现在 `Agent.context_tokens()` 一处算清,任务面板、`/history`、触发器三处同一个数。**④步数**——`max_steps` 进 config(默认 40,老 config 行为不变),撞上限后不再戛然而止:补一次**不带工具**的调用,让模型就着已经跑完的那些步骤写「已完成 / 未完成 / 下一步」,那一句「工具用完了」只活在这次请求里、不进留档;这次调用失败就静默退回旧行为
- **记起上次 + 就地改答**(v0.9.41):`search_history` 工具 / CLI `/find` / 侧栏搜索框是**同一份算法的三个消费者**,而留档在 `APP_DIR/sessions`(工作区围栏之外),所以模型侧走的是受控出口 `session.history_hits`——只取用户与助手正文(工具往返不进结果)、只给会话时间与工作区目录名、绝对路径不下发,网页版明确排除并写了理由。回答下面 👍/👎 旁多一颗 **↻ 重新生成**:撤掉这段答复、照原样重跑那句提问(不复用「编辑重发」那条路,因为它会丢掉当时那张图);点过的 👎 仍留着,那是差评回灌要的信号。

## 沙箱

Agent 能碰到什么,由四层边界决定:

| 边界 | 行为 |
|---|---|
| 敏感路径(`~/.yinluxs`、`~/.ssh`、`~/.aws`、`~/.gnupg` …) | **永远拒绝**,任何权限模式、任何用户授权都不能越过 |
| 工作区内路径 | 直接放行 |
| 工作区外路径 | 默认**逐次确认**;用户放行后本回合内有效;`allow_outside_workspace: true` 则直接放行 |
| 脚本内容(v0.9.39 起) | `py_script` / `bash python x.py` 要跑的文件先按行扫一遍(只扫前 200KB),把**命中的那几行原文 + 行号**摆进确认框,分「碰密钥位置 / 走出工作区 / 要联网或再起子进程」三类 |

命令侧:灾难命令照旧硬拒绝(`rm -rf /`、`format c:`、fork 炸弹…);沙箱还支持
`allow_network: false` 禁掉 curl/wget/ssh 等联网命令、`deny_patterns` 加自定义正则
(如 `git push`)、`timeout_seconds` 收紧命令执行超时上限。
子进程这边另有一层:环境变量里名字像凭据的(`*_API_KEY`、`TOKEN`、`SECRET` …)默认摘掉,
摘了哪几个会在输出末尾告诉你;不想摘就设 `sandbox.strip_env_secrets: false`。
**边界要说得出自己拦不住什么**:脚本内容级扫描只负责"把可疑行摆到你面前",不给子进程做隔离;
`allow_network` 是按命令名 / 脚本导入扫的门禁,**不是操作系统防火墙** —— 真要断网得用虚拟机级隔离。

GUI 顶栏的「🛡 沙箱开/关」可随时切换(写回 config.json);CLI 用 `/sandbox [on|off]` 查看或临时切换。
注意:**沙箱边界优先于权限模式**——`accept_all` 也不能让 Agent 在没有确认的情况下访问工作区外。
**档位越高越信任你,不是越信任外面来的东西**:要密钥的脚本、访问凭据目录的脚本、扫出外传出口的脚本,
**在 `full` 档也一样弹确认**。
沙箱判的「工作区」就是「工作区」那一节选定的文件夹:**换工作区,围栏跟着换**,
且切换时会清掉本回合已放行的工作区外路径(不把旧授权带到新工作区)。

## 工作区

**Agent 在哪个文件夹里干活,由你定。**

| 入口 | 说明 |
|---|---|
| GUI 顶栏「📁 工作区」 | 弹窗里选:当前 / 默认 / 最近用过;点一行即切过去 |
| CLI `/workspace` | 无参=查看当前与最近;`/workspace <文件夹路径>`=切换;`/workspace default`=回默认 |
| CLI 启动参数 | `--workspace "D:\我的资料"` / `-w`(也可写 `--workspace=...`) |

- **默认工作区** = 程序目录(exe 旁 / 开发态仓库根),也就是改造前写死的那个,老用户无感。
- **只接受已存在的文件夹**:不做隐式创建(免得在用户盘上凭空长出目录);
  `~/.yinluxs`、`~/.ssh`、系统凭据目录这类放钥匙的地方**永远不能**当工作区。
- **切换的代价说清楚**:旧会话运行器一律停掉(它的工具上下文与 system prompt 都是按旧工作区装的),
  从新会话开始;有任务在跑时**直接拒绝**,不偷偷换掉正在运行的围栏。会话留档不丢,
  侧栏里不属于当前工作区的历史会话会标出 `📁 目录名`,提醒你那些文件不在当前文件夹里。
- **记忆是全局一份**(`workspaces.json`,跟 exe 走):GUI 与 CLI 读到的是同一个「上次在哪干活」;
  记录的文件夹被删/改名时静默回退默认工作区,绝不因为一个失效设置拦启动。
- 网页版(对外形态)**不开放**工作区管理:访客按 POST 调那四个方法一律被拒,前端也会把胶囊整个藏掉。

## 附件(文件 / 图片)

聊天框左侧 📎 打开系统文件选择框,可以多选:

- 文件先复制进工作区 `uploads/`(重名自动加 `-1`/`-2`),消息里注入相对路径清单,
  模型用 `read_file` / `bash` 等工具自行处理 —— PDF 这类二进制不会被硬塞进上下文;
- 图片另做压缩:长边超过 1536 等比缩小,JPEG/WebP 逐级降质量到 1MB 以内,
  带透明的 PNG 保持 PNG,GIF 保留动画;单文件上限 20MiB、解码后不超过 4000 万像素;
- `config.json` 里 `vision: true`(且模型确实支持看图)时,图片会以 base64 data URL
  随消息直接发给模型;否则只给路径并在消息里注明「当前模型不支持看图」。
- **恢复旧会话时附件以标签复原**(v0.9.69):图片带缩略图、文件显示名字与真实大小;
  附件文件后来被删了的,标签变灰并写明「已不在工作区」—— 不装作还能打开,
  也不补一张假的缩略图。

## 外接能力(OCR / 图表 / 图片生成 / 向量档)

这一节的规矩与其他能力同源:**"能用什么"由探测函数自己说,缺了只报缺什么** —— 每一句能力描述都要能追到一次真的执行分支,不许按模型名猜、不许静默换成"看起来成功了"。

| 工具 | 后端 | 缺了 / 不准的时候 |
|---|---|---|
| `ocr_image` | `system` = Windows 自带的 `Windows.Media.Ocr`(不联网、不含模型权重,用的系统语言包,但要一组可选 `winrt-*` 绑定);`vision` = 配置里的视觉模型(能不能看图只认 `model_probe` 的实测缓存结论) | 没装绑定就照实说没装 + 给可照抄的安装命令;认出来的字**只当待核对草稿**(本机实测:`f(x)`→`f 冈`、`x^2`→`x ^ 2`、减号 `−`→汉字 `一`),每条出口都带"后端 + 告警"两行 |
| `render_chart` | 只用标准库手写自包含 SVG(`bar`/`line`/`pie`,`MAX_POINTS = 200`) | 数据必须由调用方真给出来:少一个数就报错,**不把空缺插成 0**;`source` 印在脚注,没写就是空的;产物落 `工作区/charts/`,「撤销」不跟踪它 |
| `generate_image` | `api` = OpenAI 兼容 `/images/generations`(Key 借 `providers` 那份,不落 config.json);`card` = Pillow 把文字排成 PNG | 没配接口就只出文字卡片并写明「这是排版,不是 AI 绘图」,**绝不凭描述假装出图**;返回超过 12MB 拒绝落盘;产物落 `工作区/images/` |
| 知识库向量档 | `api`(`/v1/embeddings`,借已有供应商的 Key)/ `local`(ONNX 小模型 + 自带 WordPiece) | 两档都不可用时**只跑关键词(BM25F)**,并在检索结果里写「向量档未跑:<为什么>」——把字面匹配说成语义检索就是装饰 |

开语义档的两条路:①在 `config.json` 写
`"capabilities": {"embeddings": {"backend": "api", "provider_id": "<已有供应商 id>", "model": "<embedding 模型名>"}}`;
②源码运行时用 `python scripts/fetch_embed_model.py --repo <组织>/<仓库>` 把权重下到数据目录的 `models/`
(先写 `.part` 再改名;`--sha256 文件=十六进制` 钉过才会报"已核对",没钉只报指纹),`local` 档还要本机装得到 `onnxruntime`。
**模型权重不进安装包**;装好的便携版 / 安装版里没有 `scripts/` 这一层,所以本地权重这条路**只给源码运行的同学**。
向量索引落在数据目录 `kb-vectors/`(同样不进包),以条目正文 sha1 为键、带 `CACHE_VERSION`,改一条只重算那一条。
`capabilities` 里手写的 `api_key` 会在 `save_config` 落盘前被洗掉 —— 密钥只有 credentials 那一条路。

## 长期记忆

跨会话记住四类事实:**用户偏好**(user)/**反馈纠正**(feedback)/**项目约定**(project)/
**参考资料**(reference)。分两级作用域:

| 作用域 | 存放位置 | 适用 |
|---|---|---|
| 项目级(默认) | 工作区 `memory/MEMORY.md` | 只跟这个项目有关:技术选型、目录约定、踩过的坑 |
| 用户级(`scope=user`) | `~/.yinluxs/memory/MEMORY.md` | 跨项目通用:个人偏好、沟通习惯、常用环境 |

两个文件都是**一条一行、人工可直接编辑**的 Markdown:

```markdown
- [2026-09-13][user] 喜欢先给结论再给理由
- [2026-09-13][project] 打包前必须先关掉运行中的实例
```

模型通过 `memory` 工具增删查(`save` / `list` / `search` / `forget`),系统提示词会自动
注入两级记忆(合计截断 4000 字,用户级在前)。

**整理去重(Dream `action=dream`)** —— 对齐星瑶 Y-Code 的 `/dream` 思路,分两步:

1. **确定性去重**:同类别内按中文 2-gram 相似度聚类(整体相似 ≥0.75,或短的一条被
   覆盖 ≥0.85 视为同一条),合并时保留信息最全的正文 + 较新的日期,完全重复直接丢弃;
2. **模型归纳**(有 LLM 时):让模型合并同义、删掉被后续条目推翻的,每条压成一句话,
   输出严格 JSON;解析失败或返回空就退回第 1 步的结果,绝不把记忆整理没了。

覆盖前会把原文件备份到同目录 `history/MEMORY-<时间>.md`,所以整理永远可回溯。

入口:GUI 顶栏「🧠 记忆」(点击整理两级)、CLI `/dream [project|user|all]`、
模型在用户说「整理记忆」时自行调用 `memory action=dream`。

## MCP 服务器

支持接入任意[MCP](https://modelcontextprotocol.io)服务器,外部工具会以
`mcp_<服务器>_<工具>` 的名字挂进工具集,和内置工具一样被模型调用。三种传输都支持:
**stdio**(给 `command`,子进程按行收发)、**http**(Streamable HTTP:给 `url`,POST 过去,
响应可能是 JSON 也可能是 `text/event-stream`,`Mcp-Session-Id` 会自动带上)、
**sse**(老式 HTTP+SSE:`GET` 一条长流拿到 `endpoint` 事件后再 POST 到那条地址)。
只有网址、没有启动命令的服务器从此也能连,而且**不额外依赖任何第三方库**(走标准库 `urllib`)。

在 `config.json` 里配置(完整示例见 `config.example.json`):

```json
"mcp_servers": [
  {
    "id": "filesystem",
    "command": "npx",
    "args": ["-y", "@modelcontextprotocol/server-filesystem", "D:/data"],
    "enabled": true,
    "read_only": false,
    "description": "文件系统"
  },
  {
    "id": "remote-demo",
    "transport": "http",
    "url": "https://example.com/mcp",
    "headers": { "Authorization": "${MY_MCP_TOKEN}" },
    "enabled": true,
    "read_only": true,
    "description": "只有网址的服务器;密钥留在环境变量里,不写进 config.json"
  }
]
```

`headers` 里的 `${VAR}` 在**发请求时**才展开(`MY_MCP_TOKEN` 从环境变量取),配置文件中不落明文;
日志与报错里的 URL 一律**剥掉 query**,所以 token 不会顺着错误文案漏进对话。
`transport` 留空即按 `command` 走 stdio;`url` 缺失、`file:` 协议、不认识的 transport 会被跳过并说明。

| 字段 | 说明 | 默认 |
|---|---|---|
| `id` | 服务器标识,用于拼工具名(会规范化成字母数字下划线) | 必填 |
| `transport` | `stdio`(按 command 起子进程)/ `http` / `sse`;写 `streamable-http`、`http+sse` 等别名也认 | `stdio` |
| `command` / `args` | 启动命令,支持 `npx` / `uvx` / `python` 等(**stdio 时必填**) | 空 |
| `url` | 服务器地址(`http` / `sse` 时必填,只认 http/https) | 空 |
| `headers` | 附加请求头(值支持 `${VAR}` 展开,发请求时才代入) | 空 |
| `env` | 追加的环境变量(值支持 `%VAR%` / `$VAR` 展开) | 空 |
| `enabled` | 关掉可保留配置不启动 | `true` |
| `read_only` | 标记为只读 → 免确认直接执行;默认**需要用户确认** | `false` |
| `start_timeout` / `call_timeout` | 握手 / 调用超时(秒) | 10 / 60 |
| `description` | 显示名与工具描述前缀 | 空 |

行为约定:

- **连不上不崩应用**:命令不存在、握手超时、协议错误都只在日志里提示并跳过该服务器;
- **进程级长连接 + 退出回收**:窗口关闭 / CLI 退出时统一终止子进程,不留孤儿;
- 工具自带 JSON Schema,权限门按 `read_only` 决定免确认还是逐个确认;
- **侧栏底部的 MCP 健康行**(v0.9.70):配置了的都在 —— 连上的显示
  `服务器名(工具数)`,没连上的写「未连上」,停用的写「停用」;
  对话里增删后当场刷新。

**预设模板库(v0.9.70,对话里说「看看有哪些 MCP 预设」)**:`mcp` 工具的
`action=list_presets` 摆出内置模板 —— `everything`(官方演示,试水用)、
`sequential-thinking`(分步思考)、`filesystem`(开放工作区之外的某个文件夹,
要给 path)、`time`(时间与时区)、`fetch`(网页转 Markdown),每条都写清
本机需要什么(`npx` 要 Node.js,`uvx` 要 uv)。加的时候 `action=add` 传
`{"preset": "<id>", "path": "D:/课件"}`(要参数的预设才需要 path)——
**命令与参数以模板为准,raw 改不动**(raw 能改 command,预设就成了任意命令
执行口子);探测闸照旧真连一次,连不上不写入,并如实说本机缺什么。

## 配置项(config.json)

| 字段 | 说明 | 默认 |
|---|---|---|
| `providers` | 供应商数组:`{id, name, base_url, api_key, model}`(**保留字段**:校内分发版固定用内置校园模型) | 内置校园模型 |
| `active_provider` | 同上,不参与切换;启动时一律指向内置校园模型 | `gzasc` |
| `permission_mode` | `confirm` 变更逐次确认;`accept_all` 自动放行 | `confirm` |
| `shell` | `auto` 自动选 Git Bash→cmd;可指定 `bash` / `cmd` / `powershell` | `auto` |
| `max_output_chars` | 工具输出回填给模型前的截断长度 | `20000` |
| `max_steps` | 一个回合最多转几圈"请求模型→执行工具→回填";撞上限后停止调用工具,但会让模型把已经跑完的那些步骤**收一段尾**(那一次不带工具)。调大 = 一轮烧的 token 更多 | `40` |
| `request_timeout_seconds` | 单次 LLM 请求超时 | `300` |
| `turn_time_limit_seconds` | **一轮**最多跑多久(秒);只在两步之间收手,不强杀在跑的那一步。`0` = 不限 | `1800` |
| `session_keep_last` | 会话留档保留个数:启动时按时间删旧的(当前会话永不删)。**0 = 全部保留(默认)** —— 想开清理再写个数(如 200) | `0` |
| `subagent_time_limit_seconds` | 单个子代理最多等多久报告(秒);超时只到"不再等",那一档仍在后台跑完。`0` = 不限 | `600` |
| `feedback_recall` | 信号回灌开关:同一个词连着搜空就在工具回话末尾点一句(监控栏那一行标「×N 未命中」)、这次的问题与最近 30 天某条 👎 属同一类就给本轮一条**系统侧先验**(不进留档、不当众复述)。设 `false` 时发给模型的消息与工具回话与开之前**逐字一致** | `true` |
| `capabilities` | 外接能力的后端开关:`embeddings`(向量档)与 `images`(文生图)。**这里只写 `provider_id` 借已有供应商的 Key,别写 api_key**(`save_config` 落盘前会洗掉) | `{}`(=只有关键词检索 + 只出本地文字卡片) |
| `context_window` | 模型上下文窗口(token),用于压缩触发判断 | `131072` |
| `compact_at_ratio` | 估算 token 达窗口该比例时自动压缩 | `0.7` |
| `mcp_servers` | MCP 服务器数组(见上一节) | `[]` |
| `vision` | 当前模型是否支持看图:开启后上传的图片以 base64 随消息发送 | `false` |
| `sandbox` | 沙箱策略:`enabled` / `allow_outside_workspace` / `allow_network` / `timeout_seconds` / `deny_patterns` | 见「沙箱」一节 |

> **模型固定**:面向校内分发的版本只使用内置的广州应用科技学院模型
> (`gzasc` / `deepseek-v4-flash`),界面不提供切换入口。
> `config.json` 里若残留其他供应商配置会被保留(不删用户数据),但不会被激活;
> 顶栏模型标识是纯展示,不可点选。
>
> **内网地址不面向用户展示**:模型管理弹窗与顶栏对内置项只显示模型名,
> `base_url` 一律留空下发(见 `Bridge.get_providers` / `get_info`)。
>
> **能力自动探测**:上下文窗口与「是否支持视觉」由 `minicode/model_probe.py`
> 在启动时问一次模型服务 —— 窗口靠发一条 `max_tokens` 超限的请求、从服务端
> 拒绝文本里读真实上限(请求被拒=没生成 token,几乎不花钱);视觉靠发一张 1×1
> 图片看是否被回「not a multimodal model」。结论落 `model_caps.json`(缓存一周)
> 并发布给 `model_catalog`,任务面板的能力标签、窗口上限,以及**压缩触发阈值**
> 都会自动跟上,学校换模型/换网关不必改代码。探测走后台线程,失败只是"这次没
> 测出来",不阻塞启动。
>
> **内置模型的 Key 不随仓库分发**(本仓库公开):放在本地未跟踪的
> `config.local.json` 的 `builtin_api_key` 字段,或用环境变量
> `YINLUXS_BUILTIN_API_KEY` 临时覆盖。两者都没有时应用照常启动,只是内置模型
> 不可用;打包脚本会把 `config.local.json` 一并打进 exe,所以发给用户的包仍是开箱即用。
>
> ```json
> {"builtin_api_key": "sk-在这里填入内网模型的 Key"}
> ```
>
> 离线测试/调试可以用环境变量把当前端点临时指到别处(**不写回 config.json,
> 普通用户无需设置**),冻结版 e2e 脚本就是靠它把 exe 指到本地假 LLM:
>
> ```bash
> YINLUXS_LLM_BASE_URL=http://127.0.0.1:8000/v1 YINLUXS_LLM_MODEL=fake 引路学长-CLI.exe "任务"
> ```

## 校园主题语料库

```bash
python scripts/crawl_school_topics.py --dry-run            # 只看会抓哪些链接
python scripts/crawl_school_topics.py --only 奖助学金       # 只刷新一个主题

```
爬取结果:正文归档到 `crawled/www.gzasc.edu.cn/school-qa/`(文件名带主题前缀,附
`index.json` 清单),知识库条目写入 `kb/school-gzasc.json`(按 url 合并,重爬只更新
不丢旧数据)。学生问校园问题时,`search_knowledge` 会直接命中这些带原文链接的条目;
问细节时可加大 `snippet_chars` 一次取回更多原文。

栏目按"学生会问什么"划分:奖助学金 / 入党党建 / 团学推优 / 学科竞赛 / 证书与等级考试 /
考研升学 / 转专业与专业选择 / 选课与学分 / 教务考试 / 就业与考公考编 / 榜样风采 /
心理与情绪 / 学风与学习方法 / 招生专升本 / 校园活动与文体 / 宿舍与生活服务 /
社团与学生组织 / 军训与国防教育 / 校园新闻动态 / 学生故事与风采 / 学生事务办理 /
校园讲座与专题 / 视频与图文校园 / 服务大厅与办事入口。

正文不在文字里的页面也建成条目,保证链接能送到学生手上:

| 页面类型 | 抓到的文字 | 条目正文 |
|---|---|---|
| 正文全在视频播放器 | 0 字 | 标题 + 发布日期 + `观看地址:` 原页链接 |
| 二维码/图文操作指引(热水充值、报修、校园服务公众号) | 0 字 | 标题 + 发布日期 + `查看地址:` 原页链接 |
| 只有附件的管理办法/培养方案 | 附件名 | 标题 + 发布日期 + 附件名清单 + 原页链接 |
| 失效链接(官网把 404 也渲染成 200) | 提示文字 | 不入库(靠标题识别拦掉) |

## 两个便携版(轻量版 / 完整版)

打包版联网抓取有两个引擎:轻量版不带 crawl4ai,走内置抓取器(httpx + BeautifulSoup);
完整版把 crawl4ai 与浏览器内核一起打进去,能抓需要 JS 渲染的页面。运行时自动选择,
降级时会在工具输出里说明原因。

```bash
python scripts/build_exe.py            # 轻量版:文件夹 + zip + 单文件版 + 安装包
python scripts/build_crawl4ai_exe.py   # 完整版:文件夹 + zip + 安装包(需本机有浏览器内核)
```

| | 轻量版 | 完整版 |
| --- | --- | --- |
| 产物 | `引路学长-<版本>-win64.zip`(便携)<br>`引路学长-<版本>-setup.exe`(安装包)<br>`引路学长-单文件版.exe` | `引路学长-<版本>-crawl4ai-win64.zip`(便携)<br>`引路学长-<版本>-crawl4ai-setup.exe`(安装包) |
| 抓取引擎 | 内置抓取器(无浏览器) | crawl4ai(真浏览器,可渲染 JS) |
| 解压后体积 / zip | 约 110MB / 76MB | 约 660MB / 281MB |
| 浏览器内核 | 无 | `ms-playwright/chromium_headless_shell-*`(272MB,放在 exe 同级,不塞进 exe) |
| 适用 | 日常分发、静态站点抓取 | 需要抓 JS 页面时 |

两个安装包用不同的 `AppId`,可以**同时装在一台电脑上互不覆盖**(完整版装到
`%LOCALAPPDATA%\Programs\引路学长-完整版`);便携版则是把整个文件夹拷走就能用,
配置与会话都在 exe 同目录。

完整版的浏览器内核目录可以单独拷进轻量版目录(与 exe 同级),即把轻量版升级成完整版;
反过来删掉 `ms-playwright/` 就会自动降级,不会报错。

验收(两版都可以用同一个脚本验,断言期望的引擎):

```bash
python scripts/e2e_frozen_crawl.py
python scripts/e2e_frozen_crawl.py --exe dist/引路学长-crawl4ai/引路学长-CLI.exe --expect-engine crawl4ai
```

```bash

产物三件套(dist/ 下):
- **引路学长-<版本>-setup.exe** —— Windows 安装包(推荐分享):中文向导、
  仅当前用户安装(无需管理员)、自动创建桌面/开始菜单快捷方式、带卸载器
- **引路学长-单文件版.exe** —— 免安装单文件,双击直接用(启动稍慢)

安装包内置全部三种 exe 形态对应的 GUI 版;`config.json` 首次启动生成在安装目录;
用户数据(config/sessions/memory)卸载时保留。
