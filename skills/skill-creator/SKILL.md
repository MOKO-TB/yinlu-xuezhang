把一个重复出现的流程沉淀成一份可复用的技能。触发场景:同学说「以后这种事都按这套来」「把这个流程做成模板」,或你发现同一类请求已经在用同样的步骤回答第三次。

## 一份技能长什么样

`skills/<目录名>/SKILL.md`——frontmatter 两行 + 指导正文:

```
---
name: 短名字(与目录名一致)
description: 一句话,写清「什么时候该用这个技能」
---
(给学长的操作指导正文)
```

三条硬规矩:

1. **description 是纯文本**,不写星号、不换行,写「什么时候用」而不是「里面有什么」——它是清单里那行让模型决定要不要读全文的话。
2. **正文 8000 字以内**(超了尾部口径会被静默截断)。写「步骤 + 边界」:每一步做什么、哪些事**绝对不做**、缺信息时问谁。边界是技能的价值所在——「不代写」「不编数据」这类话必须原样写在正文里。
3. **正文里的 python 代码块是模板,按代码对待**:写完先自己跑一遍验证(用脚本工具把模板存成文件再执行),少一个转义就是同学机器上的一次真报错。格式类导出(TSV/CSV)先断「行数对不对」再断内容。

## 流程

1. **问清三件事**:这个流程的触发时机、固定步骤、哪些事绝不自动做。说不清边界就先不落盘——半成品的技能会把错误做法固定下来。
2. **起草**:正文用祈使句写给未来的自己;要引用能力就用真实存在的工具(不确定名字先查,别凭印象写)。
3. **落盘**:写到 `skills/<目录名>/SKILL.md`(用写文件工具,落盘前把草稿完整给同学过一眼);文件名用目录名,别起两个名字。
4. **验证**:记一条同类请求试试——清单里出现它、读全文正常、按步骤走得通,才算交付。

## 边界

- 不替同学决定「什么该成为技能」——重复出现两次以上的流程才值得,一次性的直接办完就好。
- 不在技能里写密钥、账号、路径之外的个人隐私;技能会随应用分发,当成要贴出去的文件来写。
- 工作区 `.commands/` 里一条提示词模板就能解决的,不必升级成技能(模板更轻,改起来更快)。
