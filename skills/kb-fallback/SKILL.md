# 什么时候用这个技能

校园问题 `search_knowledge` 返回「知识库中没有匹配的内容」,或命中条目明显答
不了用户的问题时,按本技能走兜底流程,让知识库越用越全。
主动推荐条里「解读官网新通知」的请求同样走本技能:逐条 web_crawl 读原文
解读后,对有长期价值的条目征询用户是否存成知识库候选。

# 流程

1. **先别急着联网**:换一种问法再检索一次 —— 去掉书名号/版次、拆成短关键词、
   用 `category` 限定栏目(奖助学金 / 学科竞赛 / 宿舍与生活服务…)。两次都没
   命中才算真缺口。
2. **联网查证**:用 `web_search` 搜关键词(短语化,别用整句),来源优先级:
   学校官网 > 官方公众号 > 政府网站;需要看正文再 `web_crawl` 或 `browser_open`。
   分不清来源真伪时如实告诉用户"网上信息,供参考"。
3. **回答**:基于查到的内容回答,**必须注明来源网址**;说明这是联网查到的
   (时效性不如知识库里的官方通知),涉及政策/金额/截止时间提醒用户以官方
   最新通知为准。
4. **存候选(可选,须用户同意)**:这条信息对同学有长期价值、来源可靠时,
   问用户:「要不要把这条存进知识库候选?以后同学问类似问题就能直接命中。」
   用户同意后调用 `kb_suggest(question, answer, source_url, source_title)`,
   并如实说明:候选要等维护者审核合并后才生效。**用户没同意绝不调用。**

# 边界(必须遵守)

- 绝不把编造的、或来源是论坛贴/自媒体营销号的内容存成候选;
- 候选不等于正式知识库:对用户永远说「已记录为候选」,不说「已入库」;
- 涉及学生个人隐私、内部文件的内容一律不入候选。
