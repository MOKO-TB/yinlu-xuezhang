# 适用场景

同学发来课表想让你帮忙整理、看懂,或问「今天/明天有什么课」「下周开始上
第几周的课」。

# 前提(截图需要视觉模型)

- 截图形式的课表需要**支持视觉的模型**:内置校园模型不支持看图。用户在
  「模型管理」里自配了视觉模型并切换后才能看图;拿不准时先如实说明,请同学
  把课表**复制成文字**发来。

# 整理课表的步骤

1. 解析出每门课的要素:**课程名 / 星期 / 节次 / 周次 / 地点 / 教师**。缺要素的
   用"(未标注)"占位,不要替课表编。
2. 周次记法要展开说清,例如「1-16 周(单周)」= 第 1、3、5…15 周上课;
   「1-8 周,11-16 周」= 两段。同一课程单双周地点/老师不同时要明确标出。
3. 排成 markdown 表格:行 = 节次,列 = 星期一~星期日;地点写在课程名下方
   加粗。表格后附一段"这学期节奏"小结(最早一节、课最密的一天)。
4. 易错点主动提:
   - 一期/二期教学楼隔得远,连堂换楼要留出赶路时间(可以用校园地图工具把
     两栋楼框出来给同学看);
   - 早八、午休连堂、晚上课这些时间坑;
   - 单双周差异。
5. **作息钟点不编**:第几节课对应几点上课,知识库/校历里没有就如实说
   「每节课的具体钟点以教务处作息时间表为准」。
6. 问「今天有什么课」:系统环境里有今天日期,自己换算星期;再按课表的周次
   判断今天在第几周(学校教务处校历通常以开学第一周为基准 —— 开学日期校历
   里没有就先说明无法确定周次,把当天**所有可能的课**列出来并注明原因)。
7. **整理完就存下来**(否则下次问"今天有什么课"又要从头解析):
   - 先问同学一句「这学期第一周周一是几号?」(开学日期,周次推算的锚点,
     不知道就不要瞎猜,问了再存);
   - 把每门课整理成条目调 schedule(action=save, term_start=周一日期,
     classes=[{name, day(1-7), weeks("1-16"/"1-8,11-16"/"1-16(单周)"),
     periods, start_time(课表里写了才填,没写就留空), location, teacher}]);
   - 存成功后告诉同学:以后直接问「今天/明天有什么课」就行,不用再看图;
     调课/换教室时说一声,你会更新覆盖。
   - 之前存过课表的同学再发新图(换学期/调课):解析完直接 save 覆盖,
     并简述和旧课表的差别(哪几门变了)。
