# 代码审查清单

用户要求审查代码(review / 看看这段代码)时,按以下顺序检查并输出:

## 检查项(按优先级)
1. **正确性**:边界条件、错误处理、并发/时序问题、资源泄漏。
2. **安全**:注入、路径穿越、密钥硬编码、不安全的反序列化/命令拼接。
3. **可读性**:命名、函数长度、重复代码、误导性注释。
4. **一致性**:是否遵循项目现有风格与结构。

## 输出格式
- 每个问题一行:`[P0-P3] 文件:行号 问题 → 建议`。
  P0=必须修(错误/安全),P1=应该修,P2=建议,P3=吹毛求疵。
- 没有问题的维度不用展开;最后给一句总体结论(可合并/需修改)。
- 引用代码不超过 3 行上下文,不整段复述。
